# v4.2 · 匹配用户的选片结构

> 2026-08-31。这一版没有换任何模型，没有加任何付费调用。
> 它做的唯一一件有效的事，是**让输出的分布形状去匹配用户自己挑片的形状**。

---

## 一、主张变了

**v4.1 的主张**：不要用户先给正样本，agent 问一句「这趟要质量还是氛围」。

**后来实测把它削掉了大半**：

- mood 那一档只有 **2/4、p=0.11**，不显著 —— 是个可选项，不是能力
- 「问风格」这件事**一个单选框就能做**，不需要 agent
- 而人像池上 mood 其实是退化的：挑出来的 13/20 来自旅程最前 10%，AUC 0.417（低于随机）

**v4.2 的主张**：**用户自己怎么挑，就是最强的先验。**

不是「模型该多聪明」，是「输出的形状该像谁」。

---

## 二、这一版做了什么

```
用户自己挑的 20 张   最挤的 10% 时间窗口 5/20（= 随机期望），覆盖跨度 94%
v4.1 挑的 20 张      最挤的 10% 时间窗口 14/20            ← 整段端走
```

加一层**时间段配额**：按拍摄顺序切 10 段，每段最多 `ceil(target/10)` 张。

**为什么这会有效**：打分信号本身很弱（人像 AUC 0.606、风景 0.46–0.55）。
把选片挤在池子的一小段里，等于让弱信号只作用在那一小段上 ——
其余 90% 的照片连被比较的机会都没有。

---

## 三、结果

| | 交付命中 | 随机期望 | p 值 | 倍数 |
|---|---:|---:|---:|---:|
| 人像 挑 10 张 | 3/20 | 0.65 | **0.021** ✅ | 4.6x |
| **人像 挑 20 张** | **5/20** | 1.29 | **0.0056** ✅ | **3.9x** |
| 人像 挑 50 张 | 10/20 | 3.24 | **0.0003** ✅ | 3.1x |
| 风景 挑 10 张 | 2/14 | 0.87 | 0.211 ⚠️ | 2.3x |
| **风景 挑 20 张** | **5/14** | 1.74 | **0.017** ✅ | 2.9x |
| 风景 挑 50 张 | 5/14 | 4.35 | 0.451 ⚠️ | 1.1x |

对照 **v3：997 次付费调用 → 3/20、p=0.130（跟运气区分不开）**。
v4.2：**0 次付费调用、1.5 秒、确定性**。

---

## 四、提升是从哪来的 —— 三样东西，没有一样跟大模型有关

```
v4 初版             3/20   p=0.130   ⚠️ 跟运气区分不开
+ 闭眼资格门         4/20   p=0.032   ← v1 三年前就写好的免费本地能力
+ 时间段配额         5/20   p=0.0056  ← 观察用户行为得出，零模型调用
```

整个项目走到现在，最有效的两处改动：
一处是**捡回早就写好的东西**，一处是**照着用户自己的行为做**。

这跟「上更大的模型」正好相反。

## 五、必须说清的两件事

### ① 5/20 意味着什么

**你还是要自己看那 20 张，扔掉其中 15 张。**
它没有替你做决定，只是把「从 309 张里翻」变成「从 20 张里挑」——
**省的是翻找，不是判断。**

### ② 风景那个 5/14 是运气，不是能力

风景上所有指标 AUC 都是 0.46–0.55（等于随机），而且只有 K=20 显著，
K=10 和 K=50 都不显著。那个 5/14 来自「摊开」这个结构恰好在 K=20 撞对，
**不是因为它会判断风景好坏**。

代码里保留了风景警告，agent 每次都会说。

## 六、一个对这个项目性质的诚实判断

被问到「agent 是不是没起到评估照片的作用」—— **对，而且比这更彻底。**

排序链路九个环节全部在本地，大模型一张照片都没看过。
对话模型读到的只有 `p266 分数 +1.84 场景组 F99` 这样的文本行。

把这几轮实跑拆开，agent 只做了四件事，而**每一件表单都能做**：

| agent 做的 | 换成表单/CLI |
|---|---|
| 把「挑 20 张最好的」翻译成参数 | 三个输入框 |
| 转达结果 + 三条必报事项 | 结果页写死 |
| 解释「为什么分数负的也入选」 | 一段静态说明 |
| 导出两步确认 | 一个确认弹窗 |

**所以现在这个形态下，agent 层几乎没有产生一个表单做不到的东西。**

这条弧线是完整的：

- **v3** 把大模型用在它最不擅长的事上（无锚点绝对打分）→ AUC 0.497
- **v4** 把它从打分里拿掉 → 交付 5/20、0 次付费调用
- **v4.2** 发现：拿掉之后，**剩下的活它也不是非做不可**

### 还没测的三类请求 —— 表单确实做不了

- **复合约束**：「挑一些能发朋友圈的，但别都是同一天的，也别有别人入镜」
- **迭代修正**：「这批太糊了，再挑一批」→ 它得判断该换 style 还是调参数
- **异常诊断**：结果反常时自己去查是哪个机制挡的

**如果这三类它也做不好，诚实的结论就是：这个任务不需要 agent，
需要一个好的本地工具加一个好的界面。** 那个结论本身也值得记下来。

## 七、天花板

20 张金标里 13 张排在 60 名开外，它们是**环境人像**（人小景大），
而两个人脸模型**都**对小脸系统性低估（中位 33 vs 56）。

够到那 13 张需要理解「这是个好瞬间」—— 本地指标做不到。
**所以 5/20 大概就是纯本地方案的实际水平。**

再往上要么需要一个任务对口的新模型，要么回到 VLM ——
而 VLM 那条路 v3 已经证伪过一次。
