# v4.7 · VLM 裁判第一次被真正测出来

**一句话**：改一处措辞让一致率翻倍，但仍未过线；而「平局过多」有一半是任务本身就难。

## 起点：一个不能用的数字

第一轮全量评测（47 对 / 94 次调用）：

```
T0 AB/BA 一致率   11/47 = 23%      通过线 ≥60%   ❌
T2 准确率         10/47 = 21%
判平局            36/47 = 77%
```

看起来是「VLM 不行」。但逐题核对时发现根因在别处。

## 根因：提示词里的序数有歧义

一次调用发 18 幅图（14 幅整组锚点 + 4 幅考题）。而提示词里：

```
system 说：「你会依次看到：第一张的全景、第一张的人脸、
            第二张的全景、第二张的人脸」   ← 这里「第一张」指第一张**照片**
user 说：  「现在看最后四张图：第一张和第二张，哪一张更值得留下」
            ← 这里可以理解成最后四幅里的第 1、2 幅
```

而那两幅**都属于同一张照片**（它的全景 + 它的人脸）。
也就是说模型可能一直在拿一张照片跟它自己比 —— 那当然判平局。

第 7 题的理由「第二张眼神睁开到位」说的却是一张明显闭眼的照片，
就是这个歧义的直接表现。

### 改法

三处都去掉序数：

- system 明确列出「第 N 幅 = 照片甲/乙的什么」，并写明**不要拿第 1、2 幅互比**
- user 改成「照片甲和照片乙，哪一张更值得留下」
- 工具枚举 `FIRST/SECOND` → `JIA/YI`（枚举名本身也有序数歧义）

### 效果：图一张没换，模型没换，题目没换

| | 改之前 | 改之后 |
| --- | --- | --- |
| 10 道体检题 · 准确率 | 5/10 = 50% | **7/10 = 70%** |
| 10 道体检题 · 一致率 | 6/10 = 60% | **7/10 = 70%** |
| **47 对全量 · 准确率** | 10/47 = 21% | **15/47 = 32%** |
| **47 对全量 · 一致率** | 11/47 = 23% | **21/47 = 45%** |
| 47 对全量 · 平局 | 36/47 = 77% | 26/47 = 55% |

一致率几乎翻倍，而且理由的措辞也变了：

```
改前「第一张眼神睁开到位；第二张眯眼」   ← 指代不明
改后「甲闭眼，乙眼神睁开到位」          ← 明确指向照片
```

## 但按事先定死的线：仍未过

```
T0 一致率 45%  <  通过线 60%     ❌
```

**这条线不因为「已经改善很多」而放宽。当前状态：阶段 2 的 VLM 裁判不达标，不上线。**

## 「平局过多」是什么

用户提出可能是图不够清晰。实测否定：

```
                  平局对    分胜负对
人脸占画面        0.0034    0.0021    ← 平局的脸反而更大
组内睁眼差        0.027     0.097     ← 差 3.6 倍
```

平局那些对**本身就极其接近**。抽 8 对做盲判，**6 对我本人也分不出高下**，
只有 2 对明显（一张闭眼）—— 而那 2 对我的判断与用户完全一致。

所以：不是图不清楚，是任务在这些对上确实难。
但模型在我能判的那 2 对上也判了平局，说明它仍有真实的短板。

### 一个更根本的发现

**用户对每一对都有明确偏好，而我在 6/8 上看不出依据。**

可能的解释：用户做标注时看的是**整组 6 张**，模型看的是**一对 2 张** ——
信息量根本不同。同组里的相对比较，拆成两两之后就丢失了。

## 三处必须更正的旧结论

| 我早先报的 | 实际 |
| --- | --- |
| 「VLM 21% vs 本地分 79.5%」 | **比错了**。这 47 对是从「本地分判错的」里挑的，本地分在这批上 **0/47**，VLM 救回 15 对 |
| 「n=2 冒烟通过」 | 冒烟其实撞上了 `maxTokens: 400` 上限，整轮中断 —— 400 对会推理的模型太小，已改 2000 |
| 「T1 体检题最小差距 0.014，一眼能判」 | 错。0.014 不是一眼能判，已加 ≥0.10 门槛，10 对全部人工核过 |

## 顺带修掉的三个真 bug

1. **视觉调用的图片数上限写死 2 张** —— v3 遗留（1 张基线 / 2 张对比）。
   v4 一次要发 18 张。上限提到 24 但保留，它是「照片不外泄」的护栏之一。
2. **`maxTokens: 400` 太小** —— 会推理的模型思考 token 也算输出预算，
   18 张图的题目上经常没写到工具调用就用光，整轮中断。
3. **`run_pair_eval` 绕过了 `allowedRoots` 校验** —— 其他工具都校验，只有它直接用
   考题文件里写的路径。「照片只能来自授权目录」有一处例外就不成立了。

## 还没做的

- **换模型验证**。所有结论都建立在 MiniMax-M3 一个模型上。
  「这个模型在成对视觉比较上摇摆」和「VLM 这条路走不通」是两回事。
- **多次采样取多数**。每对问 4 次而不是 2 次，直接打击剩余的摇摆。代价翻倍。
- **给模型看整组而不是一对**。这是上面那个「信息量不同」的直接推论，但会改变赛制。

## 评测方式本身的问题

用户指出：这套测试太黑盒，线上用户根本用不了。

```
预生成 pairs JSON     真实用户做不出来
27 组人工标注         不会做，也没理由做
run_pair_eval         生产 profile 里根本没这个工具
```

出路是把两件事合并：**让「选片」这个动作本身产生标注**。
用户看一组连拍、挑一张 —— 那不是标注任务，那就是选片本身。

这也解释了个人口味探针为什么失败：我要求用户**先**标注**再**使用，
那个顺序本身就是错的。
