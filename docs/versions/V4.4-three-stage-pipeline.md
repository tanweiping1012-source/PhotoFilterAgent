# v4.4 · 三阶段完整链路

**一句话**：组内选优这一步以前从来没有真正发生过；接上之后挑 20 张从 5 中提到 6。

## 之前的链路缺了一段

v4.3 及以前只有一条通路：

```
打分 → 分组 → 带配额地挑
```

分组只被用来限制「同一组最多进几张」，**谁当组内冠军完全由全局分数顺序决定**。
也就是说三阶段里的第二段是空的。

## 现在

```
阶段 0 · 扫描（本地，确定性）
   缩略图缓存 → CLIP embedding → 质量指标 → Swift 引擎（人脸质量 / 睁眼程度 / 俯仰角）

阶段 1 · 过滤废片（一票否决）
   闭眼门：睁眼程度 < 0.22 且非低头 → 拒
   低头：报出但不否决（当门会误杀 2 张用户精选）

阶段 2 · 组内选优（可插拔裁判）
   分组：CLIP 余弦 98 分位 + 贪心组长
   每组擂台赛：本地分最高当擂主，其余降序挑战，平局擂主不下台
   组内名次成为**第一排序键**，全局分数退为第二键

阶段 3 · 全局精选
   候选 = 各组按组内名次排序（阶段 1 拒绝的不进）
   时间段配额（10 段）+ 家族上限 2
```

## 裁判为什么可插拔

阶段 2 是唯一可能花钱的地方。做成可插拔是为了能**分开回答两个问题**：

- 赛制本身对不对？ → `OracleJudge`（拿标注当答案），应当接近满分
- 裁判判断力如何？ → `LocalJudge` / `VlmJudge` 对比

混在一起时，一个坏结果无法归因 —— 分不清是赛制错了还是模型不行。

三个实现：

| 裁判 | 用途 | 花费 |
| --- | --- | --- |
| `LocalJudge` | 生产默认。本地分比较 | 0 |
| `ReplayJudge` | 回放 TS 侧跑完的 VLM 裁决 | 视对局数 |
| `OracleJudge` | **仅测试**。看了答案，不可上线 | 0 |

## 实测结果（人像 309 张 / 20 张精选）

### 阶段 1 · 过滤废片

```
睁眼程度覆盖         100%
拦下闭眼             52 / 309
误杀 20 张精选        0/20   ✅
误杀 35 题可接受       0/29   ✅
```

### 阶段 2 · 组内选优（128 组，169 局擂台）

| 裁判 | 冠军落在用户可接受范围 |
| --- | --- |
| 瞎选（期望） | 44% |
| **本地分（0 次调用）** | **10/17 = 59%** |
| VLM | — 配额耗尽，未跑 |
| 先知（验赛制） | **17/17 = 100%** ← 赛制上限 |
| 用户自己重做的一致率 | 50% ← 人类天花板 |

**先知裁判拿到满分**，说明擂台赛本身不丢分：挑战者顺序、平局擂主不下台、
cap 截断，都没有把正确答案挤掉。剩下的差距全在裁判的判断力上。

### 阶段 3 · 全局精选

| 挑几张 | 命中 | 瞎蒙期望 | 倍数 | p |
| --- | --- | --- | --- | --- |
| 10 | 3/20 | 0.6 | 4.6x | 0.021 |
| **20** | **6/20** | 1.3 | **4.6x** | **0.0007** |

### 接上阶段 2 带来的变化

| 挑几张 | 没有阶段 2 | 有阶段 2 |
| --- | --- | --- |
| 10 | 3/20 | 3/20 |
| **20** | 5/20 | **6/20** |
| 50 | 9/20 | **10/20** |

**这个改动本身就有收益，与裁判无关。** 原因：组内名次当第一排序键之后，
每个组的冠军都排在所有组的亚军之前 —— 相当于又加了一层多样性约束，
和时间段配额是同一个道理。

代价仍是 0 次付费调用、1.7 秒、确定性。

## 一个被我误诊的问题

先知裁判第一次跑只有 16/17，我据此写了「赛制本身在丢分」。

错了。是 `OracleJudge` 只从第一张照片查组键。标注只覆盖了每组里能检出人脸的
那部分照片，擂主经常是没被标注的那张 —— 这时可接受集合为空，
**任何对局都返回平局**，擂主永远不下台。表现出来像赛制丢分，实际是裁判瞎了。

改成从两张里任意一张查得到就行，先知立刻拿到 17/17。已加测试守住。
