# 版本演进

这个目录记录每一版**当时是怎么想的**、**做了什么**、**最后测出来是什么结果**。

保留失败的版本不是为了存档，是因为这个项目里最有价值的产出恰恰来自一次失败：
第三版花了 997 次付费调用，证明了「让视觉大模型给照片打分」这条路在这个任务上等于掷硬币。
没有那 997 次，第四版就没有理由把主干挪到本地。

| 版本 | 核心思路 | 结果 | 文档 |
|---|---|---|---|
| v1 | 本机技术指标筛坏片 | 能判断「能不能用」，不能判断「好不好」 | [V1](V1-local-metrics.md) |
| v2 | 视觉模型逐张评分 + 相似组比较 | 第一次能按画面内容出名单，但仍以排除坏片为主 | [V2](V2-vision-scoring.md) |
| v3 | 六维 rubric + 双向盲比 + BT 排序 + 独立盲审 | **997 次付费调用 → AUC 0.497（= 随机）** | [V3](V3-agent-rubric.md) |
| v4 | 排序主干挪回本地，大模型只做否决 | 0 次付费调用 → 交付 3/20（与 v3 打平） | [V4](V4-local-first.md) |
| **v4.1** | **不要正样本，agent 问一句「要质量还是氛围」** | **人像交付 3–4/20（六成运行过显著线）；换一批照片仍需重新选方向** | [V4.1](V4.1-ask-the-style.md) |

## 一句话总结这五版

v1 问「这张照片有没有毛病」，v2 问「模型觉得这张几分」，
v3 把 v2 的分数用一整套审计机制包起来，
v4 发现**问题出在分数本身**、于是换了产生分数的方式，
v4.1 发现**连「什么算好」都得先问一句** —— 同一个人不同旅行，要的是相反方向的东西。

> v4 的文档保持原样未改，包括那些后来被推翻的主张。
> 只看结论看不出「一个看起来很有道理的想法是怎么被自己的数据否掉的」，
> 而那个过程是这个项目最有价值的产出。
