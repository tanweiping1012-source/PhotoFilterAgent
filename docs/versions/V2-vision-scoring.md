# v2 · 让视觉模型看图打分

> 时间线：v1 之后。第一次引入付费视觉模型。

## 当时的想法

v1 证明了技术指标判断不了「好不好」。那就让能看懂画面的视觉大模型来判断 ——
把照片缩小、去掉元数据，发给模型，让它给个分。

## 做了什么

- **两级预览**：全池用 512px 低清扫一遍，只在边界上用 1536px 高清复看。
  这是为了控成本 —— 全部用高清太贵。
- **相似组比较**：同一场景的 2–4 张照片放在一起让模型比，比逐张打分更容易分辨。
- **缓存**：每张照片的评分结果按内容缓存，重跑不重付。
- **导出确认**：生成名单后要用户单独确认才复制文件，只复制不移动。

## 结果

第一次能真正「按画面内容」出名单了。但有两个问题在当时没被解决：

**问题一：连拍组过早折叠。** 一组连拍先选一个代表，代表再去跟别人比。
但代表是按 ID 顺序选的 —— 也就是随便选的。一次实测里，20 张最终名单中有 5 张是闭眼照，
因为闭眼那张恰好是组里 ID 最小的。

> 后来的修复：代表改成按质量排序选（闭眼 → 人脸质量 → 清晰度 → ID），
> 闭眼代表从 2 降到 0。但更根本的修复是 v3 的「全池评分，不提前折叠」。

**问题二：没有独立证据。** 主 Agent 自己挑了一份名单，然后自己说这份名单是最好的。
没有任何机制能证明它没有漏掉更好的照片。

## 留给后面的

- 512/1536 两级预览、匿名 JPEG、缓存、导出确认，这几项一直保留到 v4。
- 「主 Agent 说好不算好」这个问题直接催生了 v3 的独立盲审。
- 一个当时没意识到的隐患：**整套流程建立在「模型给的分数是可靠的」这个假设上，
  而这个假设从来没被验证过。** v3 把这个假设推到极致，v4 才去测它。
