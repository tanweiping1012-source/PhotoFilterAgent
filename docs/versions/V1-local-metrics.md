# v1 · 本机技术指标

> 时间线：项目起点。这一版完全不联网、不花钱。

## 当时的想法

旅行回来几百张照片，最直接的痛点看起来是「有一堆废片」——糊的、闭眼的、过曝的。
那就先把废片挑出来，剩下的用户自己看。

## 做了什么

一个 Swift 命令行引擎，只用 macOS 自带能力：

| 能力 | 谁提供 | 用来做什么 |
|---|---|---|
| 人脸检测、人脸质量分 | Apple Vision | 判断有没有人、脸清不清楚 |
| 图像解码、EXIF、缩略图 | ImageIO | 读原图和拍摄信息 |
| 清晰度（拉普拉斯方差） | 自己写 | 判断糊不糊 |
| 曝光直方图（死黑/死白占比） | 自己写 | 判断过曝欠曝 |
| 64-bit 灰度感知哈希 | 自己写 | 找近重复 |
| 人像/风景分类 | 自己写（基于 Vision 的人脸结果） | 分两类分别处理 |

输出是一张匿名候选表：分类、相似组、技术指标，不含文件名和路径。

## 结果

分类准确率很高，废片检测也可用。**但它回答不了用户真正的问题。**

技术指标只能判断「这张能不能用」。一次旅行里绝大多数照片技术上都合格 ——
309 张人像里，清晰度和曝光都过关的有 200 多张。用户要的是从这 200 多张里挑 20 张，
而技术指标在这 200 多张之间几乎是平的。

## 留给后面的

- 本机扫描 + 匿名化这套管线一直用到 v4，没改过。
- 「照片绝不移动、删除、改名」的只读约束从这一版立下。
- 一个后来被验证很重要的发现：**人脸质量分本身就有信号**（v4 实测 AUC 0.608）。
  当时把它当成「筛废片」的工具，其实它是个弱排序器。
