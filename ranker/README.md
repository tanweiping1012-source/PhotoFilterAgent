# PhotoFilter Ranker (v4)

> 从一堆旅行照片里挑出最值得留下的那几张。**全程在你自己电脑上跑，不上传照片，不花钱。**

---

## 这是解决什么问题的

旅行回来 500 张照片，你想挑 20 张发朋友圈。

最烦的不是修图，是**选**：同一个瞬间连拍了 15 张，看起来几乎一样；
大部分照片技术上都没毛病，但只有少数几张真的好看；一张张放大对比要花掉一整个晚上。

市面上的「AI 选片」大多在做另一件事 —— **排除坏片**（糊的、闭眼的、过曝的）。
但你的问题不是坏片太多，是**好片太多，得从好里挑更好**。

---

## 我们的方案（以及为什么是这个方案）

最自然的想法是：把照片发给能看图的 AI 大模型，让它打分，取前 20。
**我们试过了，花了 997 次付费调用，结果等于掷硬币。**

原因很实在：让 AI 在 0–100 的标尺上给照片打绝对分，它每次调用都在重新想象这把尺子。
同一张照片评两次，分数能差出 7 分 —— 而 309 张真实旅行照片彼此的差距只有 6.7 分。
**尺子的抖动比要测的差异还大。**（完整诊断见 [v3 版本记录](../docs/versions/V3-agent-rubric.md)）

于是 v4 换了个思路：

### 想法一：好照片的信息藏在「图像向量」里，不在「模型给的分」里

CLIP 是个把图片变成一串 768 个数字的模型。这串数字（叫 embedding）编码了画面内容 ——
谁在里面、什么姿势、什么光线、什么氛围。它是**确定性**的：同一张图算一万次结果完全一样，
没有任何噪声。

### 想法二：通用审美不等于你的审美

我们测了 6 个专门训练来判断照片好不好看的模型：

| 模型 | AUC（0.5 = 掷硬币） |
|---|---:|
| liqe | 0.449 |
| clipiqa+ | 0.473 |
| nima（AVA 美学） | 0.481 |
| **付费大模型六维打分** | **0.497** ← 997 次调用 |
| topiq_iaa | 0.512 |
| musiq-ava | 0.548 |
| **laion_aes** | **0.583** ✅ |
| **topiq_nr-face（人脸质量）** | **0.606** ✅ |

全都挤在 0.45–0.61 之间。这不是模型不够强，是**「大众觉得好看」和「你觉得值得留下」
本来就不是同一件事**。天花板就在 0.6 左右。

> **一个反直觉的插曲**：两个过线的模型加权融合，AUC 升到 0.624，
> 但前 20 命中从 4 张掉到 3 张，跨 K=10/20/30/40/50 一致变差。
> 因为它们**互补**（各自命中 4 张金标，只重叠 2 张），
> 平均会把各自笃定的头部拉平。所以冷启动**只用一个指标**，按人脸检出率自动选。
> 详见 [`quality.py`](photofilter_rank/quality.py) 顶部。

### 想法三：那就从你自己的选择里学

有意思的是，全表最好的 laion_aes，本身就是「CLIP 向量 + 一个线性打分头」——
而那个打分头是用**陌生人的**审美打分训练出来的。

那把打分头换成**你的**呢？

| 你标了几张喜欢的 | AUC | 比不标更好的概率 |
|---:|---:|---:|
| 0（冷启动） | 0.606 | — |
| 3 | 0.555 | 27% ← 太少，反而更差 |
| 5 | 0.610 | 52% |
| 10 | **0.673** | **77%** ✅ |
| 15 | **0.713** | **78%** ✅ |

**标 10 张，就远远超过了 997 次付费调用的 0.497。**
标少于 8 张不如不标，所以工具会自动判断该用哪种模式，不需要你操心。

### ⚠️ 但是：标注**怎么选**，比标几张重要得多

这是我们踩到的最大的坑。同样标 10 张：

| 标注选法 | AUC |
|---|---:|
| 分散在整批照片里 | **0.670** |
| 连着标旅程前半段 | **0.439** ← 比不标（0.606）还差，比随机（0.5）还差 |

因为 CLIP 向量强烈编码「场景内容」。只标一个地点的照片，
模型学到的是**「像那个地方的照片」**，不是「好照片」，换到新地点就是反向预测。

工具会自动检测这个问题并拒绝使用你的标注：

```
⚠ 标注太集中（集中度 1.14 > 1.05）：这 10 张看起来来自同一段行程或同一个地点。
  这种标注会让模型学成「像那个地方的照片」而不是「好照片」，实测比不标还差，
  所以本次退回冷启动。请把标注分散到整批照片里再试。
```

**所以：翻完整批照片再标，别在开头连着点十下。** 而且这 10 张不需要专门去标 ——
你翻照片时顺手点几个喜欢的就够了。

## 它具体怎么工作

```
你的照片文件夹
      │
      ├─ 1. 扫描 + 降采样        原图 40MP 太大，缩到 1024px 存一份缓存（309 张约 60 秒）
      │
      ├─ 2. 算 CLIP 向量         每张变成 768 个数字（0.084 秒/张，全池 26 秒）
      │
      ├─ 3. 打分
      │     ├─ 标注 <5 张 → 冷启动：人脸质量 或 laion_aes（按人脸检出率自动选） AUC ~0.61
      │     ├─ 5–11 张   → 两者线性过渡（样本太少时探针方差大）
      │     ├─ ≥12 张    → 你自己的口味模型                              AUC ~0.67–0.71
      │     └─ 护栏：标注太集中 → 退回冷启动并警告（见下）
      │
      ├─ 4. 场景分组             用 CLIP 向量的余弦相似度找连拍/近重复（免费，向量已经有了）
      │
      └─ 5. 按分数取前 N          每个场景组最多取 2 张，避免 20 张里 15 张是同一个瞬间
```

**整条链路是确定性的**：同样的照片、同样的标注，永远给同样的结果。
这一点比 AUC 数字更重要 —— 因为可复现，才谈得上「改进」。

## 上手

### 装环境

需要 Python 3.9+，macOS / Linux 都行（Mac 上会自动用 GPU 加速）。

```bash
cd ranker
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

第一次运行会自动下载模型（CLIP 约 900MB，其余约 400MB），之后就不用再下了。

### 最简单的用法：直接挑 20 张

```bash
python -m photofilter_rank.cli pick ~/Pictures/冰岛旅行 --target 20
```

输出：

```
候选 309 张 · 指纹 ca88cc18 · device=mps
  缓存完成 309 张，58s
  embedding 完成 (309, 768)，26s

模式 cold（0 张标注）· 309 张候选 · 41 个场景组 · 315.0s

选出 20 张：
   1. DSCF9127.JPG   +2.31
   2. DSCF8993.JPG   +2.04
   ...
```

### 更好的用法：告诉它你喜欢什么

建一个文本文件，每行写一个你喜欢的照片文件名：

```
我喜欢的.txt
────────────
DSCF8850.JPG
DSCF9012.JPG
DSCF9188.JPG
...
```

10 张以上效果最好。然后：

```bash
python -m photofilter_rank.cli pick ~/Pictures/冰岛旅行 --target 20 --labels 我喜欢的.txt
```

模式会自动从 `cold` 切到 `personal`，你标过的那些会直接置顶
（你都亲口说喜欢了，不需要模型再判断一次）。

### 想知道它到底准不准

如果你手上有一份「标准答案」（自己认真挑出来的精选），可以直接测：

```bash
python -m photofilter_rank.cli eval ~/Pictures/冰岛旅行 \
    --gold 我的精选.txt --target 20
```

```
=== 评测 · cold 模式 · 冷启动指标 face ===
  AUC            0.606   (0.5 = 掷硬币)
  前 20 命中      4/20    随机期望 1.29
  超几何 p 值     0.0316  ✅ 显著
  头部提升        2.51x   (K=10/20/30/40/50 平均，相对随机)
  候选 309 张 · 耗时 315s · 付费调用 0 次
```

这五个数字的含义见 [怎么判断一个选片器行不行](../docs/MEASUREMENT.md)。
特别注意「头部提升」—— 只看 AUC 会选错方案，我们真的踩过这个坑。

### 想知道该标几张

```bash
python -m photofilter_rank.cli curve ~/Pictures/冰岛旅行 --gold 我的精选.txt
```

```
协议 production（复刻产品真实条件）

标注数                探针 AUC       冷启动       胜过冷启动
--------------------------------------------------
3             0.555±0.063     0.606        27%

10            0.673±0.076     0.605        77%  ✅
```

`--protocol research` 会给出更好看的数字，但那是乐观上界 ——
它假装「你没标到的好照片」不存在于训练集里，而产品里它们就在那儿当负样本。

## 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--target` | 20 | 要挑几张 |
| `--labels` | 无 | 你喜欢的照片清单，每行一个文件名 |
| `--exclude` | 无 | 要跳过的子目录（相对路径），做评测时用来排除答案目录 |
| `--device` | auto | `mps`（Mac GPU）/ `cuda` / `cpu` |
| `--cold` | auto | 冷启动指标：`auto` / `face` / `laion_aes` / `blend`（blend 只为复现「融合更差」） |
| `--cache` | `~/.cache/photofilter-rank` | 缓存位置 |
| `--json` | 无 | 把完整结果（含全部分数、分组）写到文件 |

更细的阈值在 [`photofilter_rank/config.py`](photofilter_rank/config.py) 里，都有注释说明为什么是这个值。

---

## 关于你的照片

- **原图只读。** 全程只读取，不移动、不删除、不改名、不写回。
- **不上传。** v4 的排序链路完全在本机，没有任何网络请求。
- **缓存在你自己电脑上**（`~/.cache/photofilter-rank`），可以随时删。
- 仓库里不含任何照片或缓存。

## 现在还做不到什么

诚实的清单：

- **只在一个用户、一个文件夹、20 张标注上验证过。** AUC 的 ±0.07~0.10 是几百次随机划分的
  标准差，方向可信，绝对值别当准。换一批照片、换一个人，数字会变。
- **「不融合」和「集中度阈值 1.05」都是看着同一份答案定的**，有过拟合风险 ——
  前者有跨 5 个 K 值的一致性支撑，后者有 146 个划分的支撑，但仍然只有一个数据集。
- **集中度指标假设编码器的基线余弦是个正数**（CLIP 是 0.798）。换编码器要重新校准；
  基线太低时代码会拒绝判断而不是给假警报。
- **只测过人像。** 风景用的是同一套流程，但没有人工答案来验证。
- **场景分组的松紧没法验证。** 排序有人工精选可以对，但「哪几张算同一个瞬间」
  没有答案集，所以阈值只能靠观察定。实测一组连号照片会被分成 4 组 ——
  同组上限确实生效（20 张分布在 14 组、每组最多 2 张），
  但你可能觉得其中某几张本来就该算一组。用 `--target` 调整或直接看 `--json` 里的分组。
- **没有「否决」环节。** 闭眼、糊脸、人被切一半这些，本地向量判断不了，
  需要视觉模型补一刀。这部分设计好了但还没实现，见 [v4 版本记录](../docs/versions/V4-local-first.md)。
- **第一次跑要下载约 1.3GB 模型**，之后才快。
