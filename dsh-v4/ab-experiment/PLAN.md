## 1. 项目是什么

### 1.1 要解决的问题

一次旅行拍 5000 张,回家一张也没整理。核心矛盾:**连拍里挑哪张,人自己都要犹豫**。

### 1.2 三个阶段

```
阶段1  过滤废片      跑遍全部 N 张      必须本地（5000 张 = 5000 次调用，成本不可行）
阶段2  组内选优      连拍组内两两比较   可以用模型（133 张 → 55 局）
阶段3  全局精选      配额与覆盖         纯本地
```

**AB 实验只测阶段 2。**

### 1.3 关键机制

| 机制 | 做什么 | 在哪 |
|---|---|---|
| CLIP ViT-L/14 | 768 维向量 → 认出「哪些是一组的」,98 分位自适应阈值 | `dedupe.py` |
| Apple Vision | 人脸质量(AUC 0.711,全场最强单指标)、闭眼、pitch | `engine/` Swift |
| pyiqa | `topiq_nr-face`(有脸) / `laion_aes`(无脸) | `quality.py` |
| 资格门 | 目前**只拦闭眼** | `rank.py:96` |
| 擂台赛 | 本地分最高当擂主,其余依次挑战,平局擂主不下台,封顶 8 | `pipeline.py run_tournament` |
| 时间段配额 | 按拍摄顺序切 10 段,每段最多 `ceil(target/10)` 张 | `dedupe.py` |
| 同组配额 | `family_cap = 2` | `config.py:157` |

> ⚠️ **实测发现:`family_cap` 目前根本不起作用。**
> 在 me自然瀑布线 上跑 cap = 1/2/3/4/无上限,交付命中**完全相同**(2/36);
> 20 张选中的照片来自 **20 个不同的组,每组最多 1 张**。
> 真正在约束的是时间段配额(10 段 × 2 = 20,正好等于目标数)。
> 早先「family_cap 挡掉 10/36 金标」的说法不复现,不要再引用。

### 1.4 运行环境

DSH(DeepSeek Harness),我们的能力以 cordis 插件挂载。**隔离在 `$DSH_HOME=~/.dsh-v4`**,不碰 `~/.dsh`。

```

         photo-v4-headless 生产（命令行）
         photo-v4-eval-web 评测（web）
```

**动手前先跑 `bash dsh-v4/doctor.sh`** —— 它查五层是否同步(插件链接 / Swift 二进制 / preset / 进程启动时间 / 缓存 schema),这五层每一层都真实踩过。

## 2. 这个实验要回答什么

### 2.1 问题

**给模型看这个人自己的判断标准,它跟这个人的一致性会不会变高。**

标准有两种给法,是**两条不同的信息通道**,不是同一件事的两个剂量:

| | 形式 | 擅长表达 | 能不能带走 |
|---|---|---|---|
| **规则** | 558 字文本 `rubric/rubric-prompt.txt` | 可陈述的判据与优先级 | ✅ 用户能改 |
| **范例** | 14 张标注过的照片 = 28 幅图 | 说不清的东西(「眼神有神」长什么样) | ❌ 每次传 ~1MB |

### 2.2 为什么是现在

原本判断是「先补本地能力,再跑 AB」。**那个判断基于一个已被推翻的前提。**

项目里长期写着「v3 让模型打分,997 次调用交付 3/20,证明打分不可靠」。
复查发现这是混淆的:

```
v3 规格（512px 整幅）   人脸中位数 45px · 25分位 34px · 最小 21px
                        <96px 占比 100%   ← 96px 是本项目自己在 sent_image_check.py 定的门槛
v4 现在发的人脸特写                448px   ← 线性分辨率 10 倍
```

在 45 像素的脸上判「眼神有没有神」,评分当然抖。σ=7.28 vs 6.72 这个**测量**没错,
错的是**归因** —— 那测的是「看不见时的猜测方差」,不是「打分这种形式的固有噪声」。

> **「模型在能看清脸 + 规则清楚的条件下能做到什么」,这个项目至今没有干净地测过一次。**

v4 现有的那次 VLM 测量(47 对、32% 准确、45% 双向一致)也不干净:
题是专挑本地分判错的,还叠加了当时未修的序数歧义。

## 4. 实验设计

### 4.1 三臂

```
无提示        什么都不给                    ← 基线
仅规则        只给 rubric（558 字，零图片）
规则加范例     rubric + 范例锚点（28 幅图）

⚠️ **臂名不用字母。** 早先脚本里 A=有锚点、文档里 A=什么都不给，
跑完喂判分脚本标签会整个反过来，而且结果看起来完全正常。
这个项目已经在「符号的含义要靠记」上栽过四次，名字自带含义就没有这个问题。
```

| 对比 | 回答 |
|---|---|
| **仅规则 vs 无提示** | 标准能不能写下来传递 —— 「沉淀成通用 rubric」的真问题 |
| **规则加范例 vs 仅规则** | 范例在规则之上还有没有增量 |
| **规则加范例 vs 无提示** | 原本设计的两臂实验 |

**「仅规则」如果单独就够用,交付形态就变了。**

### 4.2 考题 —— 教材与考卷按轮次切开

用户决定**不新标注**。所以考题用第二轮**已有的**标注,教材只用第一轮:

```
教材   第一轮 35 组（雪山 eval-people-309）  → rubric v2 + 范例锚点
                                              锚点本来就来自这里
考卷   第二轮 40 组（冰海岸 + 天鹅湖）        → 去重后 33 组 / 81 对，已有答案

两轮照片重叠 0 张（内容哈希实测）· 天然跨场景 · 不需要新标注、不需要复制照片
```

**这解决了「归纳和验证同源」** —— rubric v2 只从第一轮归纳,考卷里一张
第一轮的照片都没有。泄题终检:教材 106 张 ∩ 考卷 79 张 = **0**。

⚠️ **代价:rubric v2 比 v1 弱。** 取舍句从 22 条降到 8 条,
并且**丢了最硬的一条「眼睛压过曝光」**(它只出现在第二轮)。
另外「嘴部」「眼神游离」两条判据第一轮完全没有。
详见 `../rubric/rubric-v2-holdout.md` 的对照表。

**不要凭印象把 v1 的条目补回 v2** —— 补了就等于把考卷的信息漏进教材。

### 4.3 真值:必须换成配对标注

**现有的 81 对真值是从散文答案里抽的,不能直接用。**

**① 真值抖动比要测的效应还大。** 12 组有效重测:

```
两次方向相同        19   24.4%
两次方向相反         2    2.6%   ← 真正判反的，极少
一次给方向一次判平    22   28.2%   ← 绝大部分「不一致」是这个
两次都判平          35   44.9%
```

**排序是稳的(两次都给方向时 19/21 = 90.5%),飘的是及格线。**
而现有 81 对里 **90.1% 是相邻层**,正好落在及格线上。

**② 标注者的稳定性按判据分层,差 4 倍:**

| 判据 | 重测一致 |
|---|---|
| 对焦 / 低头 / 眯眼 / 抿嘴 | **100%** |
| 闭眼 | 80% |
| 眼神无神 | 60% |
| 瞪眼 / 曝光 / 五官 | **25%** |

*(每格 3–25 个判断,样本小;分层干净且有机制解释,方向可信。)*

> **不舒服的推论:必须交给模型的那部分(眼神、氛围),恰恰是标注者自己最不稳的部分。**
> 上限被真值压着,不是被模型压着。

**结论:换成让标注者直接「两张选一张」** —— 强制给方向,及格线不参与,天花板 44% → 90%。

### 4.4 样本量与功效 —— 诚实地说,这一轮功效不足

组级置换检验,基线 56%:

```
设计                +10pt   +15pt   +20pt
本轮 81 对            26%     48%     73%
（对照）全标 252 对     71%     97%    100%
```

**81 对只能可靠发现 +20pt 以上的效果。** 真实效果如果是 +10~15pt,
大概率跑出「测不出差异」—— 而那**不等于没用**。

这一条在跑之前就写死:**不显著时,结论一律是「这个样本量看不见比 17% 更小的差距」,
不许改口径重算。**

## 5. 成本

```
主分析   81 对 × 2 方向 × 3 臂 = 486 次
同层档   75 对 × 2 方向 × 3 臂 = 450 次   ← 探索性，是否纳入待定
合计                              936 次
标注：0 —— 用第二轮已有的标注
```

**同层档要不要一起跑,是个取舍:**

| | 只跑主分析 486 次 | 加同层档 936 次 |
|---|---|---|
| 答的问题 | 「在能一眼判向的对上,X 有没有增量」 | 加上「在判等价的对上,模型会不会硬选」 |
| 风险 | 万一结论是「没增量」,可能是因为把锚点最该起作用的人群移走了 —— 486 次答了个偏的问题 | 多花 450 次,而同层真值只有 ~61% 可重现 |

建议:**一起跑**。选择偏差是事后补不回来的 —— 先跑 486 次得到「没差异」,
再回头补同层档,前面那 486 次的解释力已经被削掉了。

配额紧张时可先跑 **无提示 vs 规则加范例 两臂(324 次)**,「仅规则」后补 ——
但它是「rubric 能不能传递」的唯一证据,别永久省掉。

## 6. 判分（跑之前定死，跑完不改）

### 6.1 主检验：组级置换

同组的对**不是独立观测**。把条件标签**整组对调**做置换。

实测(模拟,真实效果 = 0):当锚点效果按组变化时,

```
组间效果离散度      McNemar    组级置换    应该是
  0                 3.8%       3.9%        5%
  0.10              6.2%       4.0%        5%
  0.20              7.0%       3.9%        5%
  0.30              11.9%      2.4%        5%
```

**McNemar 误报率涨到 12%,置换稳在 5% 以下。** 锚点是雪山照片,
对不同考题场景贴近程度不同,效果按组变化几乎必然 —— 正落在 McNemar 失灵的那一类。

同时报 McNemar(`ab_verdict.py` 已有),两者不一致时**以置换为准**。

### 6.2 平局：主指标不变，但必须拆开

模型答平局**仍然算答错** —— 从交付看,「分不出」等于没给出信息。

但要另报两个数,否则两种完全不同的情况会给出一样的结论:

```
情形甲  平局 55→20，非平局准确率都是 71%   总准确率 32%→57%   实际判断质量没变，只是不再弃权
情形乙  平局都是 55，非平局准确率 71%→98%   总准确率 32%→44%   判断质量真的提高了
```

上一轮实测模型 **55% 答平局**,所以这不是假想问题。要报:

```
总准确率（平局=错）   ← 主指标
非平局准确率          ← 下判断时对不对
平局率                ← 多久弃权一次
```

### 6.3 分层报告

me自然瀑布线 / 那批133张 各自的方向。两层一致 = 跨场景重复验证。
⚠️ 分层只回答「方向一不一致」,**不回答「显著不显著」** —— 单层样本量不够。

### 6.4 参照系

本地分在同一批对上的成绩。**付费模型至少要赢过它,否则这一档该关掉。**
(现有 81 对上本地分 45/81 = 55.6%。)

### 6.5 三种结论，预先定义

| | 判定 |
|---|---|
| 置换 p<0.05 且该臂更好 | 有显著帮助 |
| 置换 p<0.05 且更差 | 显著有害 |
| 不显著 | **测不出差异** + 同时说明「这个样本量下多大差距才测得出来」 |

**「不显著」不等于「没用」。** 写进脚本输出,不靠人记得。

## 8. 已知的坑（都已修，别再踩）

| 坑 | 后果 | 修法 |
|---|---|---|

| **拿标注目录当哈希比对基准** | `_待标注-连拍组` / `_AB实验-标注` 里是**重编码过的副本**(01.jpg…),跟原图字节不同,哈希天然对不上 —— **会把「有重叠」也算成 0**,泄题检查静默失效 | 只用**原始批次**目录做基准(`corpus-groups.json` 记的就是原始路径) |
| **`MAX_JPEGS_PER_CALL = 2`** | v3 遗留,挡住 18 图负载 | 改 40 |
| **agent 瞒报成本** | 报「0 次付费调用」实际花了 114 次 | 算出来,不写死 |

## 9. 这个实验答不了什么

- **只有一套锚点。** 结论严格说是「**这 14 张**范例有没有用」,不是「范例这种方法有没有用」。
- **只有一个模型**(MiniMax-M3)。不外推。
- **只有一个标注者。** rubric 是这个人的审美,不是普适标准。
- **只测阶段 2。** 阶段 1、3 不在范围内。
- **只跑 primary 的话,只覆盖「标注者能明确判向」的 58% 的对。** 剩下 42% 是他判等价的,
  而那正是最难、也最可能靠范例传递的部分。结论必须带上这个限定语。
