## 一、要回答什么

**给模型看这个人自己的判断标准，它跟这个人的一致性会不会变高。**

标准有两种给法，它们是**两条不同的信息通道**，不是同一件事的两个剂量：

| | 形式 | 擅长表达 |
|---|---|---|
| **规则** | 558 字文本（`rubric/rubric-prompt.txt`） | 可陈述的判据与优先级 |
| **范例** | 14 张标注过的照片 = 28 幅图 | 说不清楚的东西（「眼神有神」长什么样） |

所以是**三臂**，不是两臂：

```
A  什么都不给                    ← 基线
B  只给规则（零图片）
C  规则 + 范例锚点（28 幅图）
```

| 对比 | 回答 |
|---|---|
| B vs A | **标准能不能写下来传递** —— 这是「沉淀成通用 rubric」的真问题 |
| C vs B | 范例在规则之上还有没有增量 |
| C vs A | 原本设计的两臂实验 |

**B 如果单独就够用，交付形态就变了**：558 字能带走、能被用户改；
28 幅图不能，而且每次调用都要传 ~1MB。

## 二、为什么这个实验现在比之前更重要

原本的判断是「先补本地能力，再跑 AB」。**这个判断基于一个已被推翻的前提。**

推翻它的是一个混淆：v3「模型判不准」的结论，与「v3 发给模型的人脸只有 45 像素」
完全纠缠在一起 —— 实测这批照片在 512px 整幅下人脸中位数 45px、最小 21px，
**100% 低于本项目自己定的 96px 门槛**。v4 现在发 448px 特写，线性分辨率 10 倍。

> **「模型在能看清脸 + 规则清楚的条件下能做到什么」，这个项目至今没有干净测过一次。**

而 v4 现有的那次 VLM 测量（47 对、32% 准确、45% 双向一致）也不干净：
题是专挑本地分判错的，还叠加了当时未修的序数歧义。

详见 [`../rubric/routing.md`](../rubric/routing.md) 的「一个被推翻的论证」。

## 三、真值：必须换成配对标注

**现在的 81 对真值是我从散文答案里抽出来的，不能直接用。** 两个原因：

**① 真值抖动比要测的效应还大。** 14 组重测（第一轮 8 + 第二轮 6，
去掉 2 组顺序没打乱的）显示：

```
两次方向相同        19   24.4%
两次方向相反         2    2.6%   ← 真正判反的，极少
一次给方向一次判平    22   28.2%   ← 绝大部分「不一致」是这个
两次都判平          35   44.9%
```

**排序是稳的（两次都给方向时 19/21 = 90.5%），飘的是及格线。**
而现在这 81 对里 **90.1% 是相邻层**，正好落在及格线上 ——
真值自带约 28% 抖动，而要测的效应可能只有 10~15 个百分点。

**② 标注者的稳定性按判据分层，差 4 倍：**

| 判据 | 重测一致 |
|---|---|
| 对焦 / 低头 / 眯眼 / 抿嘴 | **100%** |
| 闭眼 | 80% |
| 眼神无神 | 60% |
| 瞪眼 / 曝光 / 五官 | **25%** |

*(每格 3–25 个判断，样本小；分层干净且有机制解释，方向可信。)*

**不舒服的推论：必须交给模型的那部分（眼神、氛围），恰恰是标注者自己最不稳的部分。**
这压着任何一致性数字的上限 —— 上限被真值压着，不是被模型压着。

**结论：换成让标注者直接「两张选一张」。** 配对标注强制给方向，
及格线那一层根本不参与，天花板从 44% 抬到 90%。

## 四、考题设计

```
来源      me自然瀑布线（冰海岸）39 组 → 195 对
          那批133张（天鹅湖）  12 组 →  57 对
          ────────────────────────────────
          51 组 / 252 对          ← 这是这批照片的物理上限

每组封顶  6 对（避免一组主导）
重复对    +25 对（10%，左右对调）→ 量配对形式下的重测信度
形式      甲 / 乙 / 都行 / 都不行
```

**锚点与考题零重叠**（按内容哈希查，不是比文件名 ——
同一张照片在几个文件夹存了副本，比文件名会漏）：
锚点 14 张全部来自 `_待标注-连拍组`（雪山 eval-people-309），
考题一张雪山照片都没有。**每一对都已经是跨场景测试。**

⚠️ **不能只用三湖当考题**（曾考虑过）：三湖只有 5 对，
5 对全部朝一个方向时 McNemar 最小可能 p = 2×0.5⁵ = 0.0625，
**永远 > 0.05，数学上不可能显著**。

## 五、判分（判据在跑之前定死）

**主检验：组级置换检验。** 同组的对不是独立观测（某张照片确实好，
它就赢很多对），McNemar 当它们独立会高估显著性。把条件标签**整组对调**做置换。

**同时报 McNemar**（`ab_verdict.py` 已写好），两个不一致时以置换为准。

**分层报告**：me自然瀑布线 / 那批133张 各自的方向。
两层方向一致 = 跨场景的重复验证。
⚠️ 分层只回答「方向一不一致」，不回答「显著不显著」—— 单层样本量不够。

**平局单独报**：模型平局现在算答错。若锚点的主要作用是「让模型敢下判断」，
那是真效果，但会被算成准确率提升，两种解释混在一起。
所以另报：非平局中的准确率 + 平局率本身。

**参照系**：本地分在同一批对上的成绩。付费模型至少要赢过它，否则这一档该关掉。
（现有 81 对上本地分是 45/81 = 55.6%。）

### 三种结论，预先定义

| | 判定 |
|---|---|
| 置换 p<0.05 且该臂更好 | 有显著帮助 |
| 置换 p<0.05 且更差 | 显著有害 |
| 不显著 | **测不出差异** —— 并同时说明「这个样本量下多大的差距才测得出来」 |

**「不显著」不等于「没用」。** 这一条写进脚本输出，不靠人记得。

### 功效（模拟，基线 56%，含组内相关）

```
设计               +10pt   +15pt   +20pt
现在 81 对           25%     46%     75%
全标完 252 对         71%     97%    100%
```

## 八、这个实验答不了的问题

- **只有一套锚点。** 结论严格说是「**这 14 张**范例有没有用」，不是「范例这种方法有没有用」。
  要覆盖后者，得从 35 题里切两套不相交的锚点各跑一遍，再翻一倍调用量。
- **只有一个模型**（MiniMax-M3）。结论不外推到其他模型。
- **只有一个标注者。** rubric 是这个人的审美，不是普适标准 —— 这正是
  `routing.md` 里「rubric 归用户、整份进模型」的由来。
