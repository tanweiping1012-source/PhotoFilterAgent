# 图片两两对比：一次给视觉模型做的仪器标定

**被测模型** MiniMax-M3（`minimax-cn/MiniMax-M3`），`temperature = 0`
**日期** 2026-09-03 · **总调用** 394 次 · **原始逐次记录** `calls.jsonl`

这份报告写给没有参与过这个项目的人。读完不需要了解我们的代码。

## 一句话结论

> 模型**看得见图**、**能认出真实的画质差异**、**不会无中生有编出赢家**，
> 判断也确实带有真实信号（63% vs 随机 50%）。
> 但在 `temperature = 0`、**输入逐字节完全相同**的重复调用下，
> 它有 **62.8%** 的概率给出不一样的答案。
>
> 我们过去以为的"模型偏好某个位置"和"模型判断能力接近随机"，
> 经这次标定，**两条都不成立** —— 真正的原因是这个不确定性。
>
> （"62.8%" 的口径是"答案发生任何变化"，含平局↔明确。若只看两次都给出
> 明确结论的子集，同一个量是 30.3%。两个口径见第三节，都列了。）

## 一、这个测试在做什么

我们在做一个照片筛选工具：一组连拍里挑出值得留下的那张。其中一步是把
**两张照片**交给视觉模型，问"哪一张更值得留下"。

问题来了：同一对照片问两遍，把两张的前后顺序对调，模型经常给出**互相矛盾**的
答案。一致率长期只有 50% 左右 —— 正好是瞎猜的水平。

这可能有很多种原因，而它们过去**混在同一个数字里分不开**：

| 可能的原因 | 说明 |
|---|---|
| 位置偏好 | 模型可能总是偏爱排在前面（或后面）的那张 |
| 答案不稳定 | 模型可能对同一个问题本来就给不出稳定答案 |
| 没在看图 | 模型可能根本没读图，只是编了一段听起来合理的话 |
| 真的分不出 | 连拍照片差异极小，可能确实没有正确答案 |

**这次测试就是把这四件事分开。**

## 二、怎么分开的

### 办法 1：加对照条件，每次只改一个东西

同一对照片问四遍，每一遍只改一个变量：

| 代号 | 送进去的东西 | 和第一遍的差别 |
|---|---|---|
| **AB** | 照片 A 在前，B 在后 | （基准） |
| **AB2** | 照片 A 在前，B 在后 | **什么都没改**，逐字节完全相同的重复提问 |
| **AB3** | 同上，但图片重新压缩过 | 只换了 JPEG 编码，**肉眼看不出区别** |
| **BA** | 照片 B 在前，A 在后 | **只换了位置**，图片字节完全相同 |

这样一相减，每个原因的份额就出来了：

- `AB` 和 `AB2` 不一样 → 只可能是**模型自己不稳定**（输入一模一样）
- `AB` 和 `BA` 不一样 → 不稳定 **＋** 位置的影响
- 两者相减 → 位置到底占多少

### 办法 2：让答案必须来自图片本身

原来模型的答案只有"甲"或"乙"两个字。**问题是：这两个字是位置标签。**
一个根本没看图、只按位置乱选的模型，照样能答得有模有样，我们分辨不出来。

所以这次在**每张图上方加一条黑边，写一个随机 4 位编码**（比如 `K7QM`），
要求模型把它选中那张的编码抄回来。

编码只存在于图片像素里 —— **模型不看图就说不出来**。于是：

- 编码抄对了 → 它确实看了图
- 编码抄错 → 图像通道有问题，其他讨论都免谈
- 报了一个不存在的编码 → 它在编

黑边是**加在图片外面**的，不遮挡画面。（如果压在人脸上，就分不清模型是
"跟着位置走"还是"被挡住了看不见"。）

### 办法 3：两个对照组

- **"完全相同"对照**：把**同一张照片**的两个副本当成两张来问，只是编码不同。
  两者质量差异**严格为零**。此时模型若还选出一个赢家，就是在编。
- **"答案无争议"对照**：一张原图 vs 它自己被**重度模糊**的副本。
  这题模型必须答对，答不对说明整套装置是坏的，其他数字都不用看了。

### 4. 这些不一致，是什么造成的

#### ① 位置偏好 —— **测不到**

这批考题有个特点（也是它的缺陷）：正确答案**永远是排在前面那张**。
所以单看 `AB` 无法区分"模型答对了"和"模型偏爱前面那张"。
但 `BA` 把顺序对调了，正确答案跑到了后面 —— 两个方向一比就清楚了：

| 条件 | 正确答案所在位置 | 模型选中正确答案的比例 |
|---|---|---|
| `AB` | **前** | 33/46 = **72%** ±13% |
| `BA` | **后** | 38/53 = **72%** ±12% |

**两个方向完全一样。** 这是本报告里位置结论的**主证据** —— 它是边缘统计，
不依赖下面那个"变化率"用哪个口径，因此最稳。

另一条路径（用变化率相减）**得不出稳定结论**，如实记录：

| 口径 | d(AB,BA) − ε | 符号 |
|---|---|---|
| 全口径（78 对） | 52.6% − 62.8% | **−10.3%** |
| 决断子集（33–38 对） | 42.1% − 30.3% | **+11.8%** |

两个口径**符号相反**，各自置信区间（±11% / ±16%）都跨过 0。
所以正确的表述是"**位置效应测不出来**"，而不是"位置效应是某个具体的正负值"。

> 这一条推翻了我们自己之前的结论。上一轮我们记录过"模型偏好最后一张图"，
> 那个结论建立在单向的边缘统计上，这次双向对照下站不住。

#### ② 同一位置下的不一致 —— **这才是主因**

`AB` 和 `AB2` 是**逐字节完全相同的两次提问**，位置、图片、提示词、参数全都一样，
`temperature = 0`。理论上必须给出相同答案。实测：

两个口径都列出来。它们测的是不同的东西，都要看：

| 比较 | 改了什么 | **全口径**：答案发生任何变化<br>（78 对，含 平局↔明确） | **决断子集**：换成了另一张照片<br>（两次都明确才计入） |
|---|---|---|---|
| **AB vs AB2** | **什么都没改** | **49/78 = 62.8%** ±10.7% | 10/33 = 30.3% ±15.7% |
| AB vs AB3 | 只换了看不见的 JPEG 编码 | 42/78 = 53.8% ±11.1% | 12/35 = 34.3% ±15.7% |
| AB vs BA | 只换了位置 | 41/78 = 52.6% ±11.1% | 16/38 = 42.1% ±15.7% |

**为什么要两个口径**：弃权（平局 / 都不够格）时"选中的是哪一张"没有定义，
所以要谈"换成了另一张照片"就必须两次都明确。但要谈"同样的输入会不会给出
不同结果"，弃权↔明确本身就是一次结果变化，必须计入。

**给厂商的那条结论用全口径**：`AB` 与 `AB2` 输入逐字节相同，
而 62.8% 的情况下返回了不同的结果 —— 这一条不依赖任何子集选择。

⚠️ **两个口径下三行的相对高低不同**，不要只看一列就下结论：
全口径下"什么都没改"最高（62.8% > 52.6%），决断子集下"只换位置"最高
（42.1% > 30.3%）。原因是各条件的弃权率本身就在波动（`AB` 41% / `AB2` 29% /
`AB3` 38% / `BA` 32%，配对检验 p≈0.13，不显著），而决断子集是**按结果筛选**
出来的，会把这个波动折叠进去。位置结论因此不建立在这张表上，
而建立在上面那条 72% / 72% 的边缘统计。

变化的构成（49 次里）：

| 变化类型 | 次数 |
|---|---|
| 弃权 → 选了某一张 | 22 |
| 选了某一张 → 弃权 | 13 |
| 选了这张 → 改选另一张 | 10 |
| 弃权类型之间变化 | 4 |

真实例子（**两次输入逐字节相同**）：

```
第一次  选 QE6H：甲表情更自然放松，眼神柔和；乙略显僵硬紧绷
第二次  选 C7TG：乙的眼神更有神采、更生动，甲略显呆滞

第一次  选 MV4E：乙的眼睛微闭、神情更自然舒展；甲眼神略显僵硬。
第二次  选 NQKH：甲眼睛睁开望向远方更有神；乙闭眼无神且略糊。
```

**排除"会话状态串台"**：我们在另一个独立进程里重跑了 8 对。
跨进程的变化率 38%，与同进程内的 38% 完全一致 —— 这不是上下文残留，
是真实的运行间不确定性。

#### ③ 模型没在看图 —— **排除**

| 检查 | 结果 |
|---|---|
| 两张图的编码都抄对 | **310 / 312 = 99.4%** |
| 报出图上不存在的编码 | **0** |
| 说"甲赢"却给出乙的编码 | **0** |

模型确实在读图，而且读得很准。

#### ④ 模型在编造赢家 —— **排除**

把**同一张照片的两个副本**（只有编码不同）当成两张来问，36 次：

| 回答 | 次数 |
|---|---|
| 平局 | 30 |
| 两张都不够格 | 4 |
| **仍然选出一个赢家** | **2（5.6%）** |

差异严格为零时，模型 94% 的情况下如实说"分不出"。**它不会硬编赢家。**

#### ⑤ 装置本身是好的 —— **已验证**

原图 vs 它自己的重度模糊副本，10 对：**10/10 全对**。
模型能可靠识别真实的画质差异。定位探针 4/4 也能准确读出编码。

## 四、最重要的一条推论

模型**单次**判断的正确率（对级估计，每对先内部平均再对对平均）：

```
63.4% ± 7.8%      随机基线 50%
```

明显高于随机 —— **模型有真实信号。**

但我们过去的计分规则是：*正反问两遍，两次一致才算对。* 如果两次调用之间
存在这么大的不确定性，那么正确率就被**平方**了：

```
0.63² ≈ 0.40
```

而我们历史报告里三个实验组的准确率分别是 **30.8% / 38.5% / 32.1%**。

**`p²` 正好落在这个区间里。** 也就是说，过去那个"模型判断接近随机"的结论，
是计分规则叠加运行不确定性造成的假象，不是模型的真实能力。

## 五、给模型厂商的具体反馈

**现象**：`temperature = 0` 下，输入逐字节相同的重复调用，答案有 62.8% 概率改变
（n=78，±10.7%）。同一现象在独立进程间同样出现（38% vs 38%），排除会话状态。

**已排除的其他解释**：

- 不是模型没看图 —— 图内编码读取准确率 99.4%，0 次幻觉
- 不是模型能力不足 —— 注入缺陷的对照题 10/10，单次正确率 63.4%
- 不是模型乱编 —— 零差异对照题上 94% 如实答"分不出"
- 不是位置偏好 —— 正确答案在前 72%，在后 72%，完全一致

**影响**：任何"多次调用取一致"的评测方案，正确率都会被平方。
一个真实能力 63% 的模型，会被测成 40%，看起来像随机。
这会让基于该模型的评测得出错误结论 —— 我们自己就得出过。

**希望确认的问题**：

1. `temperature = 0` 在这条推理路径上是否被完整应用？
2. 视觉输入 + 工具调用（structured output）的组合下，是否存在额外的采样随机性？
3. 是否有可用的 `seed` 或其他确定性开关？

## 六、这份报告不回答什么

- **不评价模型的审美水平。** 63.4% 是对"这个用户的偏好"的一致程度，不是通用画质排序能力。
- **不评价提示词或评分标准的优劣。** 那是另一轮实验，必须排在这一轮之后 ——
  在噪声地板搞清楚之前，任何提示词对比都测不出小于噪声的差异。
- **不评价理由文本的可信度。** 编码验证只能证明模型看了图，
  不能证明它写的那句理由对应真实的观察。那需要另一个测试（把理由的标签抹掉、
  照片随机排序给人看，问这句话在夸哪一张）。

## 七、已知缺陷（如实记录）

1. **考题的正确答案永远排在前面。** 这是这批考题本身的缺陷。
   我们靠 `AB`/`BA` 双向对照绕过了它，但更好的做法是在生成考题时就打乱。
2. **随机编码只生成了 25 个不同值。** 运行脚本按考题文件分批启动进程，
   随机种子每次重新播种。经检查这不影响判别（每次调用内两个编码始终不同，
   0 次碰撞；且编码值本身与胜负无关，胜率标准差 0.075 vs 纯随机期望 0.080）。
3. **弃权率高（35.3%）导致部分子集样本偏小**，"两次都明确"的比较只剩 33–38 对，
   置信区间 ±15%。结论级别的判断都用了全部 78 对的口径。
4. **加编码黑边改变了输入**，因此本轮与历史轮次不可直接逐数字比较。
