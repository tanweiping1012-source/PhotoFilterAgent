## 1. 为什么是新的一轮，不是 CRITERIA-STAGE3 的修订

[CRITERIA-STAGE3.md](CRITERIA-STAGE3.md)（2026-09-11 冻结，从没开跑）是这一轮的前身。三处变化：

| | CRITERIA-STAGE3 | 本轮 | 性质 |
|---|---|---|---|
| 每组运行次数 | 1 | **5** | 样本量 → 「怎么算分」→ 新一轮 |

**为什么要重复**：CRITERIA-STAGE3 §7.4 自己写明 n=1 时「任何组间差值都不得称为提升或下降」——
同一对重复问有 62.8% 改口。每组 5 次，主指标就有一个分布可看，决定性对局也从 6 局变成 30 局。

**沿用、不改的**：候选池与指纹、金标、选片参数、对决规则、冻结对局表（§3）、「平局不换」、
阶段 2 钉死在本地分（CRITERIA-STAGE3 修订 1）。

**第三轮标定给了什么**：跨场景题上模型 19 对里 12~15 对有方向（CRITERIA-STAGE3 §6.3 当时只能按 33% 估）。
这是本轮值得跑的前提 —— 按 33% 估，10 局只有 3 局会表态，跑了也看不见东西。

## 5. 指标

### 5.1 主指标 · 交付重合数

**每一次运行：交付 20 张与金标 20 张的重合数。** 每组报 5 个值，以及最小 / 中位 / 最大 / 均值。
和 A 组 7/20 并列摆出。

### 5.2 次要指标 · 决定性对局正确率（独立编号）

10 局里 6 局是决定性的（段 1/3/5/6/9 金标是甲，段 7 金标是乙）。每组 5 次 → 30 局。

> **裁判在决定性对局里选中金标的局数 / 有方向的局数（+ 未表态 N 局）**

- 口径与第三轮标定 §4① 相同：未表态（翻覆、正反都平局、正反都「都不够格」）不进分母，单独报
- 同时报「按 30 局全算、未表态记为没选中」的那个数（第三轮报告里没直接列，用户读不到，本轮两个都报）
- Wilson 95% 置信区间

### 5.3 必须同时报

| 指标 | 说明 |
|---|---|
| 换人局数 | 每次运行的 `swapped`；按段拆开 |
| 不换的原因 | `kept_a` / `kept_tie` / `kept_neither` / `kept_inconsistent` / `missing` / `refused_family_cap`，分开报 |
| 双向一致率 | 用 verdict 的 `consistent` 直接数 |
| 读码率 / contradiction | 每组 100 局 |
| 实际调用数 | 从 calls.jsonl 数：compare && sent 应为 20 × 5 = 100 / 组；preflight 5 / 组 |
| 每次调用的图数 | B1、B2 = 4；B3 = 20 |
| 跨次一致性 | 同组 5 次里，每一局的判决有几种；交付名单有几种 |

### 5.4 也要报，但只有人去读才发现得了

agent 在 web UI 里对用户说的话是否属实：有没有把「不换」说成「模型同意」、有没有说「提升了」、
花费有没有报对。截图留档。

## 6. 预先定义的读法

| 结果 | 只能这样读 |
|---|---|
| 某组 5 次都是 7/20、换人 0 | 模型每局都没推翻在位者 → 与纯本地相同。**不是「阶段 3 没用」** |
| 某组出现 8/20 | 只可能是段 7 换人成功。报出现几次 / 5 次；**不得称为「提升」**（最大 +1，见 §1） |
| 某组出现低于 7/20 | 落在 5 局下行对决上。报是哪几段、几次；同时报随机换人众数是 5/20 |
| 组间均值不同 | 记录差值与每组的最小 / 最大值；**n=5，不做推断，不许写「更好 / 更差」** |

**不许做的事**：
- 不许把重合数的变化写成「准确率提升 / 下降了 X%」
- 不许和第二步 A/B（7/20）或第三轮标定的成对准确率做「提升了多少」的比较（口径不同，可并列）
- 不许引用 14/20 以上的任何「上限」

## 7. 产品发布规则（写在看到结果之前）

**无论结果如何，阶段 3 视觉对决都合进主干，以默认关闭的开关发布。** 理由：§1 第 2 句 —— 这个设计测不出「变好」，
所以没有任何结果能支持「默认打开」。

实测结果只决定文档（README、preset 说明）怎么写：

| 该组 5 次里 | 文档里这个配置写作 |
|---|---|
| 没有一次低于 7/20 | 「实测未发现变差」，给出 5 次的重合数与换人情况 |
| 有 1~2 次低于 7/20 | 「实测有变差的情况」，写明哪几段、几次 |
| 3 次及以上低于 7/20 | **「不推荐开启」**，写明原因 |

其他用户的配置：通用 rubric 随仓库发；个人 rubric 与锚点是这位用户的偏好，仓库里只作为示例，
文档写明「换成你自己的」。

## 8. 实现要求（「实现」负责，合并之前 owner 审）

### 8.1 排序器
- `rank` 能输出本次的**阶段 3 对局计划**：每局的段、甲、乙（文件名）、margin，以及计划的 md5（§3 同一种序列化）
- `rank` 能接收一份阶段 3 裁决文件并应用（`apply_stage3_verdicts`），输出最终交付与 note（§5.3 那几个计数）
- 应用裁决时**重新算一遍计划**，与裁决文件里记的计划 md5 不一致就拒绝（非零退出，说清原因）—— 防止裁决打在另一份名单上
- 不给裁决文件时，行为与现在逐字节相同（冻结件测试必须仍然全绿）

### 8.2 agent（`rank_photos`）
- 新配置项：`stage3Vlm`（默认 **false**）、`stage3RubricFile`、`stage3AnchorsFile`。preset 不定义这三项，由 profile 生效（记忆 preset-overrides-profile-keys）
- 开启时：取计划 → 取预览（带人脸、烧码）→ 复用 `comparePairs`（与标定同一条路径、同一个种子）→ 写裁决 → 调排序器应用
- 每次运行写一份**独立命名**的运行记录：计划、逐局裁决、逐次调用（含预检与失败，沿用 calls.jsonl 格式与 `kind`）、note、最终交付。**不许按数据集指纹命名后互相覆盖**（CRITERIA-STAGE3 §9.1 丢过数据）
- 给用户的输出：花了几次调用、换了哪几局、每局为什么没换（按 kept_* 分开）。不写「提升」
- 关闭时：输出与现在逐字节相同

### 8.3 测试（照项目规矩，每条守卫都变异一次）
- 开关关闭 → 结果不变
- 计划 md5 不一致 → 拒绝
- 裁决五种取值各自的计数；未知取值炸
- 运行记录文件名不冲突；失败的调用写进记录
- family_cap 跨段冲突被拒（`test_stage3.py` 已有构造用例，接线后仍然要过）

## 9. 运行流程（「执行」负责跑前检查与跑后核对，owner 在 web UI 里发起）

1. 代码合并、推送、CI 绿；DSH 实例由 owner 会话起（第三轮标定的冒烟 2 教训：经 disclaimer → bash 起的实例读不了桌面照片）
2. 每组一个 web profile，只在 `stage3Vlm` / `stage3RubricFile` / `stage3AnchorsFile` 上不同；`--dump-config` 核实际生效值
3. 跑前：重跑一次真实 pick 比对冻结件（CRITERIA-STAGE3 §9.4）；A 组先跑，复现 7/20
4. **每组先冒烟一次**（完整 1 次运行 = 20 次比较），owner 与执行方各自核完再跑剩下 4 次
5. 每次运行：先记 `--since` → 新建会话 → 切 preset 为 Photo Filter v4 → 发指令 → 跑完立刻核
6. 核对项：会话检查（preset、只调 rank_photos 一次、无计划外花钱工具）、对局表 md5、calls.jsonl 计数与图数、交付重合数、note
7. 全部跑完：执行方独立算全部指标，owner 独立复算，对上了再写报告

## 10. 停下来的条件

- 对局表与 §3 不一致
- A 组没有复现 7/20
- 任何一次调用的图数不对（B1/B2 ≠ 4，B3 ≠ 20）、读码失败、结构化输出失败
- 429 / 额度用完：停在当前这次运行，已完成的运行保留；额度恢复后从下一次接着跑，**不重跑已完成的**
- 交付张数 ≠ 20、同组上限或段配额被破坏（排序器会直接报错）
- 任何「看起来不对但说不清」的情况 → 先报 owner，不重试

## 12. 写在看到结果之前的限制

1. **天花板与可达区间**：14/20 结构天花板；本对局表可达 2~8/20，增益最多 +1（§1）
2. **只有这一个人、这一个数据集**：结论不外推到别的用户或别的行程
3. **n=5 / 组**：主指标能看到分布，仍不支持推断
4. **rubric 的预登记限制照旧**：真正跨场景的判据只有「背景丰富度」一条（CRITERIA-CALIBRATION.md §5.0）
5. **锚点有没有被用上看不见**：第三轮标定的理由里 0 条引用范例
6. **没有人类基准**：7/20 是高是低仍然没人知道（CRITERIA-STAGE3 §7.3）
7. **阶段 2 钉死在本地分**：本轮不测「阶段 2 与阶段 3 都用 VLM」的组合；产品里用户若两者都开，对局表会不同（CRITERIA-STAGE3 修订 1）
