## 3. 双向一致率 —— 这一项比准确率更值得看

```
跨层   无提示 50.0%  ·  仅规则 56.4%  ·  规则加范例 48.7%
同层   无提示 48.6%  ·  仅规则 50.0%  ·  规则加范例 40.3%
```

**50% 是纯随机作答的期望值**（两次独立乱选撞上同一张的概率 0.25+0.25）。
六个数里五个贴着 50%，一个在它之下。

判据里预先写着的通过线是 60%。**没有一组达到。**

> 模型自己前后都不一致时，准确率再高也不可信 —— 这是判据里预先定的读法，
> 不是事后找的借口。

**排下来还有一个观察：发了 28 幅范例图的那一组，自洽性是六组里最差的。**

```
跨层   规则加范例 48.7%  <  对照组 50.0%
同层   规则加范例 40.3%  <  随机基线 50%
```

同层那个 40.3% 尤其要注意 —— **低于 50% 不代表「没有偏好」，恰恰代表偏好稳定，
只不过偏好的是位置而不是内容**（永远选排在前面那张，一致率会是 0%）。

范例没有让它判得更稳，方向是反的。这和下一节那个平局倾向的解释同向。

## 4. ~~一个与数据一致的解释~~ —— **这一节的结论是错的，已撤回**

原来这里写着：范例让模型「更倾向于答分不出」，证据是同层档 50.0% → 59.7%。

**那是计分缺陷造成的假象。** 事后核对发现：

```
compare.ts   翻覆（两个方向选了不同照片）→ winner 记成 'tie'
             而同层档的真值就是 'tie'    → 判对

后果         「答对率」恒等于「1 − 双向一致率」，三组逐个吻合：
             无提示 51.4% ≡ 51.4% · 仅规则 50.0% ≡ 50.0% · 规则加范例 59.7% ≡ 59.7%

实测         判对的 37/36/43 对里，真正「两个方向都主动答 TIE」的只有 1/1/2 对，
             其余 36/35/41 全是翻覆被洗成了「对」
```

所以「规则加范例」在同层档的 59.7% 不是它更常认为分不出，
**是它更不自洽** —— 而不自洽在那一档被当成了答对。

这跟第 3 节那个观察完全一致：**那一组的双向一致率本来就是六组里最差的**
（同层 40.3%）。两个数说的是同一件事，我当时把它读成了两件。

跨层档没有这个问题（判对的 24 对里不一致 0 对）；
NEITHER 也没有（`neither ≠ tie`，翻覆记成 tie 不等于真值，照样判错）。
**只有 tie 真值这一类中招**，因为「翻覆」和「主动答平局」被映射到了同一个值。

修法已落地：`winner` 拆成五个值，翻覆记 `inconsistent`，在任何真值下都判错。
下一轮的判据见 [`CRITERIA-MERGED.md`](CRITERIA-MERGED.md)。

> 留下这一节而不是删掉，是因为**错在哪比结论本身更值得记**：
> 一个看起来自洽、两个档互相印证、还能讲出机制的解释，
> 底下是一行把两种情况映射到同一个值的代码。

## 4b. 约三分之一的题，模型不是在判断 —— 是在填模板

标注者提出一个我没想到的假设：会不会模型两次给的其实是同一张照片、
同一个理由，只是我们的位置映射把它算成了不一致。

**查下来：我们的映射没错，但他的直觉指向了更深的一层。**

把 AB 的理由里 `甲`↔`乙` 对调后再跟 BA 比 —— 若模型跟着内容走，
对调后应当更像；若跟着位置走，不对调就已经很像。
在「两次答同一槽位」的那批对上，三组一致地**对调后更不像**：

```
组          对数   原样相似   对调后
无提示        30    0.390    0.332
仅规则        25    0.466    0.379
规则加范例     28    0.448    0.301
```

实例：

```
DSCF7824 vs DSCF7821，两次都答「甲」，而甲是两张不同的照片
  第一遍 甲=7824：「甲眼神更有神、更聚焦，乙眼神略显涣散无神」
  第二遍 甲=7821：「甲眼神更集中有神…乙眼神略涣散。」
```

**同样的话给了槽位里的任何一张，连用词都一样。**

```
无提示 38%  ·  仅规则 32%  ·  规则加范例 36%
```

约三分之一的题，测的不是「判得准不准」，是「会不会套模板」。
这解释了一致率贴着 50%、准确率接近随机、以及为什么锚点不起作用 ——
**在套模板的题上，给什么提示都不会改变输出。**

⚠️ 「模板化集中在难分辨的对上」这个解释**没有站住**：
三组按睁眼差比较的方向不一致（0.030/0.023、0.023/0.030、0.012/0.041），
n≈25 太噪。模板化确实存在，触发条件未知。

**对产品的直接含义**：如果打算把理由展示给用户看，
在这三分之一的题上那段理由是编的，而用户看不出区别。
在弄清触发条件之前，理由字段不应该直接对用户展示。

详见 [`SLOT-TEMPLATING.md`](SLOT-TEMPLATING.md)。

## 7. 这一轮答不了什么

**① 「对照组」不是空白对照 —— 跑到一半才查出来。**
`compare.ts` 的系统提示词本身就带着整套判据，而且标明「顺序来自照片主人自己
35 次判断的实际频次：眼神(27/35) / 脸型与光影(8/35) / 失焦(5/35) / 构图引导物(4/35)」。
那 35 次判断正是 rubric v2 归纳的同一批。逐条比，rubric v2 的条目里
**系统提示词已经有六成**，真正新增的只有 4 条（一票否决的结构、「两张都不行」、
标准是相对的、氛围）。

→ **「仅规则 vs 无提示」这个差值不能读成「rubric 能不能写下来传递」。**
   要答那个问题，得再跑一组去掉判据的提示词。
→ 主结果「规则加范例 vs 无提示」仍然有效，但准确说测的是
   「在已含判据的提示词之上再加范例」。

**② 功效不足。** 78 对只能可靠发现约 20 个百分点以上的差距。
真实效果如果是 10~15 个点，这个实验看不见。

**③ 考卷只保留了标注者当初给了方向的对。** 他判平的那 42% 被移到探索性的同层档，
不进主检验 —— 而那恰好是他自己最不稳的那部分判断。

**④ 范围。** 一套锚点（结论严格说是「**这 14 张**范例有没有用」）、
一个模型（MiniMax-M3）、一个标注者。

## 7b. 一个字段坑：结果文件里的 `local_correct` 不可信

```
结果文件   对照组   False × 78        ← 全错
           仅规则   False × 78        ← 全错
           规则加范例  True 42 / False 36  ← 搬运部分的 3 对也是错的
考题文件   （真源）  True 45 / False 33
```

根因：**第一轮（20260902-2231）的结果文件就没填这个字段**，
而 `salvage.py` 是逐行忠实复制 —— 把 False 原样搬了过来。
所以凡是搬运来的行，这个字段都是旧值或空值。
症状是运行时打出 `T2 增量 —（本地分 0/0）`、`本地分判错的 0/3`。

**本报告不受影响** —— 第 1 节的本地分 45/78 = 57.7% 由
`local_baseline.py` 直接读**考题文件**算出，来源正确。

⚠️ **以后一切与本地分相关的分析，必须回考题文件取 `local_correct`，
不能读结果文件。** 否则「模型救回了本地分判错的几对」这类分析，
在搬运过的组上会算出全错的数 —— 而且不报错。

（`trace_run.py` 不读这个字段，本轮六项核对不受影响；它只在「泄漏」那一项里
把 `local_correct` 当作**关键词**去查理由文本，与字段取值无关。）

## 8b. 为什么锚点没起作用 —— 事后 review 找到了机制

跑完之后对着锚点本身逐项查，找到一个**系统性**的原因，
详见 [`WHY-ANCHORS-FAILED.md`](WHY-ANCHORS-FAILED.md)。要点：

```
考题真值    81% 的题「睁眼程度更高的那张赢」（60 对 vs 14 对）
锚点教的    例1 组保留的是睁眼第 3 名，例3 组第 1 名被淘汰
            —— 两组有保留项的锚点，都在演示「睁眼最好的那张反而输」
```

根因在选锚点的代码：`split_annotation` 用 **「理由最长」** 挑，
注释写的是「理由越长说明判据写得越具体」—— 这个直觉是反的。
**用户在判断显而易见时只写一行，遇到例外才写长句。**
三组锚点里两组来自最长的前五名，最长那条字面上就是转折句
「虽然眼睛没有完全睁开，但是五官舒展…」。

按理由长度排序，等于按「有多例外」排序。

另外两处：锚点文字里「其余闭眼」与图片矛盾（例3丙 睁眼 0.284，
比两张「及格」的都高）；摘要把「虽然A但是B」压成了「因为B」，
丢掉了判据优先级关系的唯一证据。

**所以这一轮测出的「锚点没有提升」，更可能是「这三个锚点没有提升」，
而不是「范例这种方法没有提升」。**

## 9. 建议的下一步（按性价比）

**① 先补对焦门，再谈模型。** 标注者最可复现的规则是「脸没对上焦」
（重测 10/10 = 100%，单独淘汰过 2 个整组），而 agent **完全没有实现它** ——
`EngineFacts` 没有任何清晰度字段，资格门只拦闭眼。`face_box` 已经有了，
框内算一次拉普拉斯方差就行。零成本、确定性、当场可验收。

**①b 换一组有代表性的锚点重跑。** 见 8b —— 现在的锚点集在教规则的反例。
改 `split_annotation` 的选择准则（从「理由最长」改成「赢家在主判据上也占优」），
不需要新标注，重跑一轮就能知道这一轮测的到底是「范例没用」还是「这三个范例没用」。

**② 要提高这个实验的功效，只有一条路：配对标注。**
让标注者直接「两张选一张」，天花板从 44% 抬到 90%，并且天然没有这一轮的选择偏差。
代价是约 30 分钟的标注。

**③ 「rubric 能不能传递」需要一个真正的空白组。**
去掉系统提示词里的判据，才能测。

**④ 平局倾向那条假设值得单独设计一轮。** 如果范例的作用真的是「让模型更常认为分不出」，
那它在「宁可不选也不要选错」的产品场景里反而是优点 —— 但这要专门测，不是这一轮的产物。
