## 3. 双向一致率 —— 这一项比准确率更值得看

```
跨层   无提示 50.0%  ·  仅规则 56.4%  ·  规则加范例 48.7%
同层   无提示 48.6%  ·  仅规则 50.0%  ·  规则加范例 40.3%
```

**50% 是纯随机作答的期望值**（两次独立乱选撞上同一张的概率 0.25+0.25）。
六个数里五个贴着 50%，一个在它之下。

判据里预先写着的通过线是 60%。**没有一组达到。**

> 模型自己前后都不一致时，准确率再高也不可信 —— 这是判据里预先定的读法，
> 不是事后找的借口。

## 4. 一个与数据一致、但**本轮无法确认**的解释

把两个档放一起，范例做的事**像是**让模型更倾向于答「分不出」：

```
跨层平局率   仅规则 43.6%  →  规则加范例 51.3%    +7.7pt
             跨层真值都有赢家 → 更爱答平局 → 准确率 38.5% → 32.1%

同层平局率   仅规则 50.0%  →  规则加范例 59.7%    +9.7pt
             同层真值就是平局 → 同一个倾向在这里是加分
```

**同一个倾向，在两个档上导致相反的分数变化，方向互相印证。**

⚠️ **但这不是发现。** 三组 p 值全不显著，平局率的差异本轮也没有做显著性检验
（平局率是预先登记的**描述性**次要指标，不是检验目标）。
把它写在这里是因为它值得下一轮验证，**不是因为它成立**。

## 6. 一个现场案例：题目有多难

跑到一半时，标注者怀疑「模型两次选不同照片」是我们发图发错了。
我按 `comparePairs` 的真实排图复刻了两遍调用的完整负载给他核对 ——
**图和标注都是对的**，两遍唯一差别就是两张照片对调位置。

他看完的反应：

> 「我现在看，可以说差不多是平局」
> ——（几秒后自行更正）——
> 「不对，还是有细微差别，5263 有一些眼神没睁开，很细微，但有差别」

**这不是「人判错了」**：他复判的方向与几个月前的原始标注一致，方向可复现。
不稳的是「分不分得出」本身。

这一对的睁眼程度差是 **0.020**，在 74 对能算该值的题里排第 41 百分位 ——
**比它更细微的还有 41%**。

```
睁眼程度差的分布（对级去重后 74 对）
  中位数            0.024
  差 < 0.02 的       41%
  差 < 0.05 的       66%
  差 < 0.10 的       88%
```

**这批考题的中位难度，就是「要看第二眼才能确定」那一档。**
这解释了为什么六个一致率都贴着随机基线 —— 不是模型偷懒，是相当多的对确实接近平局。

完整案例见 [`case-thin-margin.md`](case-thin-margin.md)。

## 7. 这一轮答不了什么

**① 「对照组」不是空白对照 —— 跑到一半才查出来。**
`compare.ts` 的系统提示词本身就带着整套判据，而且标明「顺序来自照片主人自己
35 次判断的实际频次：眼神(27/35) / 脸型与光影(8/35) / 失焦(5/35) / 构图引导物(4/35)」。
那 35 次判断正是 rubric v2 归纳的同一批。逐条比，rubric v2 的条目里
**系统提示词已经有六成**，真正新增的只有 4 条（一票否决的结构、「两张都不行」、
标准是相对的、氛围）。

→ **「仅规则 vs 无提示」这个差值不能读成「rubric 能不能写下来传递」。**
   要答那个问题，得再跑一组去掉判据的提示词。
→ 主结果「规则加范例 vs 无提示」仍然有效，但准确说测的是
   「在已含判据的提示词之上再加范例」。

**② 功效不足。** 78 对只能可靠发现约 20 个百分点以上的差距。
真实效果如果是 10~15 个点，这个实验看不见。

**③ 考卷只保留了标注者当初给了方向的对。** 他判平的那 42% 被移到探索性的同层档，
不进主检验 —— 而那恰好是他自己最不稳的那部分判断。

**④ 范围。** 一套锚点（结论严格说是「**这 14 张**范例有没有用」）、
一个模型（MiniMax-M3）、一个标注者。

## 9. 建议的下一步（按性价比）

**① 先补对焦门，再谈模型。** 标注者最可复现的规则是「脸没对上焦」
（重测 10/10 = 100%，单独淘汰过 2 个整组），而 agent **完全没有实现它** ——
`EngineFacts` 没有任何清晰度字段，资格门只拦闭眼。`face_box` 已经有了，
框内算一次拉普拉斯方差就行。零成本、确定性、当场可验收。

**② 要提高这个实验的功效，只有一条路：配对标注。**
让标注者直接「两张选一张」，天花板从 44% 抬到 90%，并且天然没有这一轮的选择偏差。
代价是约 30 分钟的标注。

**③ 「rubric 能不能传递」需要一个真正的空白组。**
去掉系统提示词里的判据，才能测。

**④ 平局倾向那条假设值得单独设计一轮。** 如果范例的作用真的是「让模型更常认为分不出」，
那它在「宁可不选也不要选错」的产品场景里反而是优点 —— 但这要专门测，不是这一轮的产物。
