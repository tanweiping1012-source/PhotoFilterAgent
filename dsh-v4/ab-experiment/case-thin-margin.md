# 案例：一对题有多难 —— 标注者自己的实时反应

> 收进报告，**不改判据**。这是一次现场观察，不是新的评分口径。
> 记录时间 2026-09-02。

## 怎么来的

用户怀疑「模型两次选了不同照片」可能是我们发图发错了 —— 标签错位、
顺序颠倒之类。于是我按 `comparePairs` 的真实排图逻辑复刻了两遍调用的完整负载
（`bundle(first) + bundle(second)`，即 甲整幅 → 甲人脸 → 乙整幅 → 乙人脸），
把两张图连同「倒数第几幅 = 谁」的标注一起发给他核对。

**结论：图和标注都是对的，排图与 SYSTEM 里的说明完全一致。**
两遍的唯一差别就是两张照片对调了位置。

## 他看完之后的反应

对 `DSCF5261` vs `DSCF5263`：

> 「我现在看，可以说差不多是平局」
>
> ——（几秒后自行更正）——
>
> 「不对，还是有细微差别，5263 有一些眼神没睁开，很细微，但有差别」

## 这说明什么，以及不说明什么

**不说明「人判错了」。** 他独立复判的方向 —— 5261 优于 5263 ——
与他几个月前的原始标注完全一致（第二轮第 6 题：「1和2都很好…3的眼神没有睁开」）。
**方向是可复现的。**

**说明的是：「分不分得出」这件事本身不稳定。**
第一反应是平局，看第二眼才定向。这正是重测数据里那个形状 ——
方向稳（两次都给方向时一致 19/21 = 90.5%），飘的是及格线
（28% 的对一次划两边、一次划同一边）。这次是它的一个现场实例。

**同时排除了两个会毁掉实验的可能：** 不是标注错，也不是我们发错图。

## 这一对在全体考题里有多典型

引擎的连续睁眼程度值（闭眼资格门用的同一个）：

```
DSCF5261 = 0.271    DSCF5263 = 0.251    差 0.020
```

在 74 对能算出该值的主分析题里（去重后的 78 对中有 4 对缺该值），
**这一对排第 41 百分位** —— 比它更细微的还有 41%。

```
睁眼程度差的分布（对级去重后）
  中位数            0.024
  差 < 0.02 的       41%   30/74
  差 < 0.05 的       66%   49/74
  差 < 0.10 的       88%   65/74
```

⚠️ 早先一版写的是 77 对（43% / 68% / 88%），那是**对级去重之前**的口径 ——
eval-me-133 和 三湖 是副本目录，同一对被数了两遍。结论没变，但数字要和
判分口径（去重后 78 对）对得上，否则读的人会以为是两个不同的集合。

**这批考题的中位难度，就是「要看第二眼才能确定」那一档。**

## 它如何解释这一轮的其它数字

| 观察 | 在这个背景下的读法 |
|---|---|
| 模型双向一致率 50.0% / 56.4% | 50% 正好是随机基线 —— 题目差异接近可分辨极限时的预期表现 |
| 模型平局率 50.0% / 43.6% | 不是模型偷懒，是相当多的对确实接近平局 |
| 三组都输给本地分 55.6% | 本地分用的正是这个连续值本身，在极细差异上它比语言判断稳 |

⚠️ **这不是给模型开脱。** 结论仍按判据走。它改变的是结论的**措辞**：
不能写成「模型判不准」，要写成
**「在一批连标注者自己都要看第二眼的照片对上，模型表现与随机不可区分」**。

## 由此引出的、这一轮答不了的问题

如果近一半的对连人都几乎分不出，那这一半**值不值得让模型去判**？
产品上，这些对无论选哪张用户大概率都不会不满意。
真正值钱的可能是差距 > 0.10 的那 12%。

「按睁眼差分层看准确率」是跑完现有数据就能算的，不用额外花钱 ——
但那是**下一轮的分析**，不进这一轮的判据。
