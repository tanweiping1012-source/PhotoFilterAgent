# 判据文件 · 通用与个人分开

## 为什么分开

`rubric-v2-prompt.txt`（第二步用，连拍组内比较）把「什么算好照片」和
「这一个人喜欢什么」混在一份文件里。那在只服务一个人的时候没问题，
但别人拿这个 agent 去跑自己的照片时，会被灌进一整套**不属于他的口味**。

所以跨场景这一份从一开始就拆成两段：

```
rubric-crossscene-general.txt              通用 —— 换谁来用都成立
rubric-crossscene-personal-example.txt     个人 —— 只属于写它的那个人
```

## 怎么判断一条该进哪一段

**问：换一个人来看这张照片，他会同意吗？**

```
会同意    闭眼、脸部全黑、张嘴说话的瞬间、眼白露太多、表情狰狞
          45 度角光源修饰脸型、脸型流畅、曝光充足、姿态自然
          → 通用

不一定    不喜欢自己张嘴笑、不喜欢低头看路、不喜欢抬头俯视镜头
          → 个人
```

判不准的时候放进**通用**并在那一条后面标注来源，不要放进个人 ——
个人段落越短越好，它每多一条，别人拿去用时就多一分被灌错口味的风险。

## 冲突怎么办

**个人段落优先。** 而且模型被要求在理由里写明「这一条是按个人偏好判的」，
这样事后能把「按通用判错的」和「按个人判的」分开看。

但个人段落**不能推翻一票否决**（闭眼、全黑）——
除非它显式地写出来要推翻哪一条。默认情况下否决项仍然先生效。

## 别人怎么写自己那一份

最省事的办法是照着 `rubric-crossscene-personal-example.txt` 的形状写几句：
自己不喜欢什么、为什么。**不必凑数** —— 三条真实的偏好，比十条编出来的有用。

这个人那三条是这么来的：给他看 20 组「他留了 A、没留 B」的照片对，
请他每组写一句为什么。20 条自由文本里拆出 14 条独立判据，其中只有 3 条是个人偏好，
其余 11 条换谁来看都成立。**这个比例值得记住：大部分判据是通用的。**
