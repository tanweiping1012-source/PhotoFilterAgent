# rubric —— 从标注里归纳出来的判据

| 文件 | 是什么 |
|---|---|
| `rubric-v1.md` | 判据全文,每条附频次和支撑原话 |
| `rubric-prompt.txt` | 提示词版(558 字),去掉证据只留规则 |
| `rubric-corpus.json` | 75 条语料:轮次/题号/场景/张数/原话/命中判据 |
| `rubric-stats.json` | 频次统计,`rubric-v1.md` 里的数字都出自这里 |
| `corpus-groups.json` | 每条语料 → 它当时展示的那几张照片(按展示顺序) |

## 飞书表格

<https://bytedance.sg.larkoffice.com/sheets/Vr30s40Fphjbc5too0zlaGWogeg>

三张子表:元规则(3 行)/ 判据分层(9 行)/ 语料证据(75 行),
配图 12 张判据示例 + **75 张语料对照图**(每条原话配它当时看到的那一组,
按 1、2、3… 编号,与原话里的编号一一对应,所以「保留1和2,3闭眼」可以直接核对)。配图是 512px 整幅 + 448px 人脸特写,
**重新编码时不带任何元数据,实测 EXIF 字段 0 个** —— 跟发给模型的规格一致。

只放人脸特写不行:第一版只有整幅图,「没对上焦」和「眯眼」在图上根本看不出来,
跟当初联系表被打回是同一个毛病。判眼睛必须给特写,判曝光和构图必须给整幅,两个都要。

## 展示顺序的权威来源

第一轮用 `_题目对照.json`(不是 `_对照表.json` —— 后者不按题号索引,
用它会对错 8 组),第二轮用 `ab-questions.json`。
两份都记录了**用户当时看到的顺序**,原话里的「1」「2」指的就是这个顺序。

顺带查到:第一轮 35 题里有 **8 题是重复组**(`kind: again`),
加上第二轮的 6 组,两轮一共 14 组重测 —— 比原先以为的 3 组多得多,
够算标注者自己的重测信度了,而那正是任何模型能达到的一致性上限。

## 这份东西的效力边界

**它是归纳,不是验证。** 75 条语料抽规则,再拿其中任何一条去检验它,
都是拿训练集自测。要证明这份 rubric 有用,必须用**没参与归纳的新标注**。
