# rubric 该怎么给 —— 按规则的逻辑类型路由,不是整份塞进提示词

## 结论先说

**这份 rubric 里只有三条该进 VLM 提示词,其余都该进代码。**

理由不是"省钱",是**规则的逻辑类型决定了它该由谁执行**:

- **门限规则**(能不能要):闭眼、脸没对上焦、低头无引导物 —— 二值、可观测、可复现
- **排序规则**(哪张更好):眼睛压过曝光、五官能救没睁开 —— 连续、相对
- **元规则**:标准相对、允许整组不要、允许平局 —— 这些是**架构属性**,写进提示词也约束不了

把门限规则写进提示词,等于让一个又贵又不稳的部件去重做一件本地 1.5 秒能算准的事。

## 证据:标注者对不同判据的稳定性差 4 倍

13 组重测,按"这对题里出现了哪些判据"分组统计照片级一致率:

| 判据 | 重测一致 | 类型 |
|---|---|---|
| 对焦 | **10/10 = 100%** | 可观测 |
| 低头 / 头歪 | **9/9 = 100%** | 可观测 |
| 眯 / 没完全睁开 | **3/3 = 100%** | 可观测 |
| 嘴部(抿嘴) | **6/6 = 100%** | 可观测 |
| 闭眼 | 20/25 = 80% | 可观测 |
| 眼神无神 | 9/15 = 60% | 主观 |
| 瞪眼 | 1/4 = 25% | 主观 |
| 曝光光影 | 1/4 = 25% | 审美 |
| 五官脸型 | 1/4 = 25% | 审美 |

**可测量的物理事实 → 100% 一致。主观审美 → 25–60%。**

⚠️ 每格只有 3–25 个照片级判断,单看任何一格都不可靠;
但分层如此干净、且有机制上的解释(可观测 vs 审美),方向可以信。

这条结果有个不舒服的推论:**必须交给 VLM 的那部分,恰恰是标注者自己最不稳的部分。**

| **脸没对上焦** | 门限 | ❌ **完全没有** | **资格门 —— 缺口** |

## 最大的缺口:对焦

`EngineFacts` 的字段是 `closed_eyes / face_quality / big_face /
eye_openness / face_area / face_box` —— **没有任何清晰度字段**。
`rank.py:96` 的资格门也只有 `blocked = facts.closed_eyes & set(names)`。

Swift 侧的 `TechnicalQualityAnalyzer` 确实算了 `sharpness`,但那是**整张图**的,
而 `eligibility.py` 自己的注释就写着:

> 说明「整张图锐不锐」和「脸清不清楚」是两件事。

所以:**标注者最可复现的一条规则(100% 重测一致、单独淘汰过 2 个整组),
agent 完全没有实现。** 而且它是本地可算的 —— 人脸包围盒已经有了(`face_box`),
在那个框里算一次拉普拉斯方差就行,零成本、确定性。

## 提示词里最终只该留三条

本地算不出来、必须理解画面内容的:

1. **眼神状态** —— 有神 / 无神 / 瞪 / 飘
2. **低头时画面里有没有视觉引导物**
3. **氛围是否成立**

其余全部下沉到资格门和本地打分。

## 这对 AB 实验的含义

范例锚点和规则文字**作用域不重叠**:

- 规则文字擅长表达**可测量**的东西 —— 而那部分本来就该由代码做,给了也是浪费
- 范例照片擅长演示**说不清楚**的东西("眼神有神"是什么样) —— 那正是剩下的三条

所以三臂实验(无 / 只给规则 / 规则+范例)测的其实是**两条不同的信息通道**,
不是同一件事的两个剂量。预期:只给规则的增量有限,增量主要来自范例。

但同时要清醒:那三条的真值,标注者自己的重测只有 25–60%。
**在这个维度上,任何一致性数字的上限都被真值的抖动压着。**
