# PhotoFilterAgent

**旅行回来 500 张照片，帮你缩到能发出去的那几十张。**

不上传、不联网、不花钱。第一次约 5 分钟建缓存，之后每次 1.6 秒。

---

## 先说定位，这决定你要不要往下看

拿一批真实旅行照片测：**309 张人像**，主人自己挑出 **20 张最喜欢的**，
程序在不知道答案的情况下挑一遍：

| 让它挑 | 撞上你的心头好 | 瞎蒙能撞上 | 碰巧的概率 |
| --- | --- | --- | --- |
| 10 张 | 3 张 | 0.6 张 | 2% |
| **20 张** | **6 张** | 1.3 张 | **0.07%** |
| 50 张 | 10 张 | 3.2 张 | 0.03% |

挑 20 张里有 6 张是你想要的，**另外 14 张不是**。

所以它是**把 309 张缩到 20 张让你自己挑**，不是替你决定。你少翻 289 张，
最后那一下还是你自己点。

> ⚠️ **风景照做不了。** 161 张风景 + 14 张人工精选，六个业界通用美学模型
> AUC 全部落在 0.46–0.55，等于掷硬币。不是没调好，是这条路走不通。
> 二次验证时甚至发现「照片里有没有文字」这种无关提示词得分一样高。

---

## 核心思路：把一件事拆成三件，因为它们根本不是同一类问题

一开始我们和所有人一样，把「帮我选照片」当成一个问题：给每张照片打个分，
排序，取前 N 张。**这条路走死了**（下面「走过的弯路」有完整记录）。

真正的转折是意识到：**「选照片」里藏着三个难度和性质完全不同的问题。**

| | 它在问什么 | 性质 | 你自己重做能一致吗 |
| --- | --- | --- | --- |
| **阶段 1** | 这张有没有硬伤？ | **客观**、二分类 | **88%** |
| **阶段 2** | 这几张几乎一样的，哪张最好？ | 良定义、可比较 | **50%** |
| **阶段 3** | **你**想留哪张？ | **主观**、信息不在照片里 | — |

那个「你自己重做能一致吗」是实测的：让照片主人隔一阵重看同一组照片，
**阶段 1 的判断（留还是整组扔）他和自己一致 88%，阶段 2（具体选哪张）只有 50%。**

这一列决定了一切：

- 它是**天花板**。阶段 2 的人类上限只有 50%，那么给程序定「准确率要 90%」
  就是荒谬的 —— 我们真的定过，比人类上限高了 40 个点。
- 它解释了**为什么三段要用三个不同的指标**。阶段 1 该看「误杀率」，
  阶段 3 该看「和精选重合几张」。用同一把尺子量三段，必然有两段量错。

## 阶段 1 · 过滤废片

### 问题的本质

「这张有没有硬伤」—— 闭眼、糊掉、低头看地。

**这是三段里唯一客观的问题**，所以最该做，也做得最好。

### 关键：指标不是命中率，是误杀率

两类错误的代价完全不对称：

```
漏杀（该删没删）  → 用户多翻几张，代价低
误杀（不该删删了）→ 用户永远看不到那张，不可逆
```

所以这一阶段的验收线是「**在零误杀的前提下，能拦下多少**」，
而不是「拦得准不准」。

### 怎么解的

用苹果自带的人脸关键点算**眼睛睁开程度**（眼睛轮廓的高宽比），
低于阈值就否决。

### 走过的弯路 ①：最强的信号一直是瞎的

「眼睛睁没睁开」是照片主人 **35 道题里 27 道**的判断依据 —— 压倒性的头号判据。

但我们发现它**在 68% 的照片上根本不存在**。

原因不是算法差，是**它在缩略图上干活**。程序为了快，先把照片缩到 1024 像素
再分析。这批是「人站在雪山前」那种环境人像，人只占画面 8% ——
缩完脸只剩 74 像素，眼睛根本看不清，程序只能跳过。

而**原图是 7728 像素宽的**，同一张脸有 564 像素，绰绰有余。

改法：**先在小图上找到脸在哪，再回原图把脸裁出来看。**
判断门槛也从「脸占画面多大比例」换成「**脸实际有多少像素**」——
后者才是关键点可靠性的真正决定量，前者把分辨率写死了。

```
眼睛能判断的照片   32% → 100%
拦下的废片         10 张 → 21 张（在标注覆盖的 106 张内）
误杀              0 → 0    ← 这条不能破
```

### 走过的弯路 ②：程序把「低头」当成了「闭眼」

改完之后，一张照片主人**自己选进精选**的照片被误杀了。

把脸裁出来一看：眼睛是睁着的，只是在低头，眼睑遮住了眼球。
判断闭眼靠的是眼睛高宽比，而**低头时这个比值同样会掉下来**。

有意思的是，**照片主人自己从来没搞混过这两件事** —— 他的标注里
「眼睛都没睁开」和「低头看路没有视觉引导物」是并列的两条理由。
是程序把两件事压成了一个数字。

修法：苹果的人脸识别本来就给**头的俯仰角**。低头的报「低头」，不报「闭眼」。
误杀归零。

### 走过的弯路 ③：想修一个公平性问题，结果修坏了

眼睛天生细长的人，睁到最大也可能低于固定阈值 —— 这是真实的公平性风险。

想的修法是**按每个人自己的分布归一化**（「这张在他自己的照片里排第几」）。
先试了按连拍组归一化：

```
              AUC     当门用：误杀 / 拦到
绝对阈值      0.911        0 / 10
按组归一      0.740        1 / 7     ← 更差
```

**按组归一永远断言「这组里总有一张最好」**，但照片主人 35 题里有 12 组是
**整组淘汰**的，其中数组的理由正是「都没睁开眼」。这个方案恰好毁掉了
最该拦下的情况。

正确的做法是按**人**归一（用他在整批照片里的分布，「整组都闭眼」仍测得出来），
但测试集基本是同一个人，按人归一 ≈ 全局归一 ≈ 和绝对阈值等价，
**在现有数据上验证不了**。这条缺口至今没补上。

### 现在的水位

```
眼睛读数覆盖率     100%
拦下              52 / 309
误杀 20 张精选     0/20   ✅
误杀 35 题可接受    0/29   ✅
```

## 阶段 2 · 连拍组里挑最好的

### 问题的本质

同一瞬间按了 6 下快门，选出该留的那一两张。

**这一阶段之所以比阶段 3 容易，是因为问题本身良定义**：组内照片在清晰度、
曝光、构图上几乎没差别，只差表情、眼神、姿态。差异维度少，就可比较。

### 怎么解的：分组 + 擂台赛

**分组**用 CLIP 特征的余弦相似度。但阈值不能写死 ——
相似度没有绝对刻度，同一个阈值在不同批照片上表现完全不同
（实测阈值 0.86 把 309 张分成了 **2 组**）。改成**按分位数自适应**。

**组内**打擂台：本地分最高的当擂主，其余按分数降序依次挑战，
**平局时擂主不下台**。只打 n−1 局而不是全循环 —— 全循环在 309 张上要
1114 次比较，擂台赛 362 次。

### 走过的弯路 ④：这一阶段以前是空的

说出来有点难堪：**在 v4.4 之前，「组内选最优」这一步从来没有真正发生过。**

分组只被用来限制「同一组最多进几张」，**谁当组内冠军完全由全局分数顺序决定**。
三阶段里的第二段是个空壳。

接上之后（组内名次成为第一排序键，全局分数退为第二键）：

```
挑 20 张   5/20 → 6/20
挑 50 张   9/20 → 10/20
```

**而且这个收益和裁判是谁无关。** 原因是：组内名次当第一键之后，
每个组的冠军都排在所有组的亚军之前 —— 相当于又加了一层多样性约束。

### 关键设计：裁判可插拔，为了能归因

阶段 2 是整条链路里唯一可能花钱的地方（让视觉模型看两张图比一比）。
做成可插拔是为了**能分开回答两个问题**：

- 赛制本身对不对？ → 用「先知裁判」（直接拿人工标注当答案），应当接近满分
- 裁判判断力如何？ → 换本地分 / 视觉模型对比

混在一起时，一个坏结果无法归因 —— 分不清是赛制错了还是模型不行。

实测（128 组，169 局）：

| 裁判 | 冠军落在用户可接受范围 |
| --- | --- |
| 瞎选（期望） | 44% |
| **本地分（0 次调用）** | **59%** |
| 视觉模型 | — 配额耗尽，未跑 |
| 先知（验赛制用） | **100%** ← 赛制上限 |
| 用户自己重做的一致率 | 50% ← 人类天花板 |

**先知拿到满分，说明擂台赛本身不丢分** —— 挑战者顺序、平局规则、
组内截断，都没把正确答案挤掉。剩下的差距全在裁判的判断力上，
那正是视觉模型该补的位置。

### 走过的弯路 ⑤：我们一度虚报了这一阶段的成绩

先前报的是「组内选优 2.29 倍于随机」。**错了。**

那个随机基线假设「每组只有一张正确答案」。而照片主人标注时被允许多选
（「这两张我都行」），实测**平均每组 4.3 张里有 1.74 张可接受** ——
真实随机基线是 44%，不是 30%。2.29 倍缩水成 **1.35 倍**。

这件事说明：**允许标注者说「都差不多」，比逼他选一个更重要。**
不然你会系统性高估自己。

## 阶段 3 · 从几百张里选出「能发朋友圈」的

### 问题的本质，以及为什么它最难

阶段 1、2 问的是「**这张照片**好不好」，阶段 3 问的是「**你**想留哪张」。

**后者的信息不在照片里，在你脑子里。** 这是性质上的区别，不是难度上的。

### 现在怎么解的：时间段配额

唯一在这一阶段被证明有效的机制，来自一个观察 ——
把照片按拍摄顺序切成 10 段，看两份名单各自怎么分布：

```
照片主人自己挑的 20 张   最挤的一段里 5 张（= 随机期望），覆盖跨度 94%
程序原本挑的 20 张      最挤的一段里 14 张          ← 全挤在一段
```

**人是「每一段各挑几张」，程序原本是「把最好的那一段整段端走」。**

而挤在一段里等于自己砍掉了覆盖面 —— 打分信号本来就弱，
只作用在池子的一小部分上更浪费。加上「每段最多 ⌈N/10⌉ 张」的配额之后，
这是所有改动里性价比最高的一处。

### 走过的弯路 ⑥：想学你的口味，学不会

最自然的想法是：让你标几张喜欢的，程序学你的口味。我们试了，**失败**。

```
标注 10–15 张时：融合后交付 1.83 → 1.57，30 次划分里只赢 7 次
```

而且有个更根本的问题：**普通用户不会先给你一批标注。** 一个要求用户先做作业
才能用的工具，不是工具。

所以现在**默认关闭**。标注会被记录，但不参与排序 —— 并且会如实告诉用户
「收到了但没用上，因为实测没有收益」，不粉饰成「正在学习你的口味」。

（同类项目 PixCull 的个性化阈值是 **≥50 张**修正。我们在 10–15 张就放弃了，
可能早了 5 倍 —— 但手上只有 20 张金标，测不了。）

### 下一步的思路

**最反直觉、但数据最支持的一条：不要直接攻阶段 3。**

看这张消融表 —— 阶段 3 的机制一行没动，光靠改阶段 1 和 2：

```
                挑20张   挑50张
两个都关          5/20     8/20
只开阶段 1        5/20     9/20
只开阶段 2        5/20     9/20
两个都开          6/20    10/20    ← 可叠加
```

**阶段 1 和 2 是阶段 3 的输入。** 废片过滤得更干净、组内选得更准，
阶段 3 的候选池就更好。这比在阶段 3 上直接加机制有效得多，
因为那一层的信号本来就弱。

具体排下来：

1. **把视觉模型接到阶段 2**（不是阶段 3）。先知裁判证明赛制上限是 100%，
   本地裁判只到 59% —— 中间那 41 个点是模型能吃的。
   评测集、四条通过线都已就绪，等模型配额。
2. **扩大阶段 1 的覆盖**。现在只有「闭眼」一条规则。照片主人的标注里
   还有「失焦」「脸型在这个光影下不流畅」「低头没有视觉引导物」——
   前者本地可测，后两者需要模型。
3. **修混合文件夹的误路由**（见下面「做不到的」第 2 条）。
4. 个人口味探针留到有 ≥50 张标注时再测。

**但要诚实：阶段 3 不会有质变。** 挑 20 中 6 已经是 4.6 倍于随机，
再翻一倍也就是 12/20 —— 而人自己重做同一批照片的一致性都成问题。
这一阶段的定位就是**缩小范围**，不是替你决定。

## 贯穿始终的一条方法论

如果你打算自己做类似的东西，这一节比上面任何一段都值钱。

### 只认交付，不认中间指标

我们有**七次**遇到「两个指标单独都有效，融合之后指标更好看，
但实际挑出来的照片反而更差」。

所以规矩是：**只看最终名单命中了几张，AUC 一律不作为决策依据。**

### 先测天花板，再定通过线

我们一度定「准确率要到 90% 才算过关」。后来才测出照片主人
**自己重做同一题的一致率只有 50%** —— 那条线比人类上限高 40 个点，定了等于没定。

现在的做法：**评测集里混入重复题**（打乱顺序、不告诉标注者），
先量出人类自己的一致率，再据此定线。

### 用无关的对照做零假设校准

风景那个负面结果，第一次只是「六个模型 AUC 都在 0.5 附近」。
第二次我们加了**故意无关的提示词**做对照：

```
「黄金时刻的光线」   AUC 0.607
「照片里有没有文字」 AUC 0.603   ← 无关轴，一样高
```

「有没有文字」和「是不是黄金时刻」得分一样高 —— 这才把「没有信号」
从猜测变成了证明。

## 怎么用

### 你需要有

一台 Mac（用到苹果自带的人脸识别）、Python 3.9+、一个装照片的文件夹。

### 装

```bash
cd ranker
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

第一次会下载几个模型（合计约 3.6GB）。**全程只下载，不上传。**

### 跑

```bash
python -m photofilter_rank.cli pick ~/Desktop/我的照片 --target 20
```

打印一份名单，**不会动你的原图** —— 不移动、不删除、不改名、不覆盖。

先小规模试试：

```bash
python -m photofilter_rank.cli scan ~/Desktop/我的照片
```

## 你的照片会去哪里

**哪里都不去。** 排序、分组、打分、判断闭眼全部在你自己的电脑上完成，
不需要 API Key，不需要联网（除了第一次下模型）。原图**只读**。

有一个可选功能会用到云端模型（连拍里两张实在分不出高下时让模型看一眼），
**默认关闭**。就算打开，发出去的也只是最长边 512 像素、
元数据全部剥掉（0 个 EXIF 字段、无 GPS）的小图，不发文件名、路径、时间。

## 已知做不到的

写在这里而不是藏起来。

1. **风景照做不了。** 六个美学模型全部等于随机，用无关对照二次验证过。
2. **混着人像和风景的文件夹会走错分支。** 程序按整个文件夹的人脸比例决定用哪套
   标准，而真实用户的文件夹就是混的。已知缺陷，还没修。
3. **只在一个人的照片上验证过。** 所有结论都建立在一位使用者的口味上。
4. **眼睛天生细长的人可能被误判。** 固定阈值理论上对不同眼型不公平。
   试过按组归一化，实测更差（见弯路 ③）。正确修法需要多人照片集才能验证 ——
   目前**没有证据**，这是真实的公平性风险。
5. **视觉模型那一档一次都没跑成。** 两个模型路由都不可用
   （一个超额、一个欠费），阶段 2 的 226 次调用评测已就绪但未执行。
