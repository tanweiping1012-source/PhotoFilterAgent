# PhotoFilterAgent

**旅行回来 500 张照片，帮你缩到能发出去的那几十张。**

不上传、不联网、不花钱。第一次约 5 分钟建缓存，之后每次 1.6 秒。

---

## 这东西到底能帮你到什么程度

先把话说在前面，因为这决定了你要不要往下看。

我们拿了一批真实的旅行照片做测试：**309 张人像**，照片的主人自己从里面挑出了
**20 张最喜欢的**。然后让程序在不知道答案的情况下挑一遍，看能撞上几张。

| 让它挑 | 撞上你的心头好 | 瞎蒙能撞上 | 碰巧的概率 |
| --- | --- | --- | --- |
| 10 张 | 3 张 | 0.6 张 | 2% |
| **20 张** | **5 张** | **1.3 张** | **0.6%** |
| 50 张 | 9 张 | 3.2 张 | 0.2% |

「碰巧的概率」越小越好 —— 0.6% 的意思是：如果程序只是在瞎蒙，蒙出这个成绩的
可能性只有六百分之一。所以它确实学到了东西，不是运气。

**但也别期待过头。** 让它挑 20 张，里面大概有 5 张是你想要的，另外 15 张不是。

所以它的定位是**帮你把 309 张缩到 20 张让你自己挑**，不是替你做决定。
你少翻 289 张，最后那一下还是你自己点。

> ⚠️ **风景照它做不了。** 我们单独测过 161 张风景，
> 六个业界通用的美学模型全部等于掷硬币。这不是没调好，是这条路走不通。
> 详见 [风景：一个干净的负面结果](docs/versions/V4.1-SCENERY-NULL.md)。

## 它把这件事拆成三步

这三步的难度差别很大，值得分开说。

### 第一步 · 扔掉废片 ✅ 做得最好

闭眼的、糊掉的、低头看地的 —— 这类照片不用你看第二眼。

程序会检查每张脸的**眼睛睁开程度**。实测：在照片主人标注过的 106 张里拦下
21 张，**一张误杀都没有**（没有把他想留的照片当废片扔掉）。

这一步为什么最靠谱：**它问的是「这张有没有硬伤」，不是「这张好不好看」。**
有没有硬伤是客观的，好不好看是主观的。

### 第二步 · 连拍里挑最好的那张 ⚠️ 有效但有限

同一个瞬间你按了 6 下快门，程序把它们认成一组，只留最好的一两张。

实测：程序挑的那张，**59% 的情况下**落在照片主人能接受的范围里；瞎选是 44%。
有提升，但没有想象中大。

而且这里有个更重要的发现：**让照片主人隔一阵子重看同一组，他自己和自己
只有 50% 的一致率。** 也就是说这个任务本身就没有唯一答案 —— 连拍里那几张
本来就差不多，程序选了另一张不见得算错。

### 第三步 · 从几百张里选出「能发朋友圈」的 ⚠️ 只能缩小范围

就是开头那张表：挑 20 张能中 5 张。

这一步最难，因为它问的不是「这张照片好不好」，而是「**你**想留哪张」——
而这个信息不在照片里，在你脑子里。

## 怎么用

### 你需要有

- 一台 Mac（用到了苹果自带的人脸识别）
- Python 3.9 以上
- 一个装着照片的文件夹

### 装

```bash
cd ranker
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

第一次跑会自动下载几个模型（合计约 3.6GB），之后就不用了。**全程只下载，不上传。**

第一次分析 309 张照片约 5 分钟（建缩略图缓存、算特征、跑质量模型）。
结果按文件夹指纹缓存，**同一批照片再跑只要 1.6 秒**。

### 跑

```bash
python -m photofilter_rank.cli pick ~/Desktop/我的照片 --target 20
```

`--target 20` 是「帮我留 20 张」。

它会打印一份名单，**不会动你的原图** —— 不移动、不删除、不改名、不覆盖。
想把选中的复制出来另说，得你再给一条命令。

### 先小规模试试

```bash
python -m photofilter_rank.cli scan ~/Desktop/我的照片
```

`scan` 只数一下有多少张、有多少张有人脸，几秒钟出结果，不算分。

## 它背后最反直觉的一件事

**我们试过让 AI 大模型给每张照片打分。那条路是死的。**

第三版就是这么做的：让视觉大模型按六个维度给每张照片打分，再加上双向盲比、
独立盲审、熔断机制一整套。**花了 997 次付费调用，最后测出来等于掷硬币。**

问题出在哪？让同一个模型对**同一张照片**打两次分，两次差 7.28 分；
而**不同照片之间**的真实差距只有 6.72 分。

> **噪声比信号还大。** 后面那一整套审计机制，都是在给噪声做质检。

第四版把打分挪回本地 —— 用你 Mac 上现成的算法。结果是：

| | 第三版（大模型打分） | 第四版（本地算法） |
| --- | --- | --- |
| 花钱 | 997 次调用 | **0 次** |
| 耗时 | 数十分钟 | **1.6 秒**（缓存后） |
| 跑两次结果一样吗 | 不一样 | **一样** |
| 命中你的精选 | 3/20（不显著） | **5/20（显著）** |

**这个项目最值钱的东西，是那 997 次失败。** 没有它，就没有理由把主干挪回本地。

## 一个真实的排错故事

这个故事能说明这个项目是怎么做事的。

「眼睛睁没睁开」是最重要的判断依据 —— 照片主人做标注时，35 道题里有 **27 道**
提到了眼神。

但我们发现：**这个信号在 68% 的照片上根本不存在。**

原因不是算法差，是**它在缩略图上干活**。程序为了快，先把照片缩到 1024 像素
再分析。这批照片是「人站在雪山前面」那种，人只占画面很小一块 ——
缩完之后脸只剩 74 个像素，眼睛根本看不清，程序只好跳过。

而**原图是 7728 像素宽的**，同一张脸有 564 像素，绰绰有余。

改法很直接：**先在小图上找到脸在哪，再回原图把脸裁出来看。**

```
眼睛能判断的照片    32% → 100%
拦下的废片          10 张 → 21 张
误杀（扔掉了好照片）  0 → 0    ← 这条不能破
```

改完之后又冒出一个新问题：程序开始把**低头的照片**判成闭眼。

因为判断闭眼靠的是「眼睛的高宽比」，而**人低头的时候眼睑会遮住眼球，
高宽比同样会掉下来**。有一张照片主人自己选进精选的低头照，就这么被误杀了。

有意思的是，**照片主人自己从来没搞混过这两件事** —— 他的标注里
「眼睛都没睁开」和「低头看路没有视觉引导物」是并列的两条理由。
是我们的程序把两件事压成了一个数字。

修法：苹果的人脸识别本来就能给出**头的俯仰角**。低头的照片报「低头」，
不报「闭眼」。误杀归零。

完整记录：[v4.3 · 眼部判定搬到原图](docs/versions/V4.3-eyes-on-full-res.md)

## 你的照片会去哪里

**哪里都不去。**

- 排序、分组、打分、判断闭眼 —— 全部在你自己的电脑上完成
- 不需要 API Key，不需要联网（除了第一次下载模型）
- 原图**只读**：不移动、不删除、不改名、不修改

有一个可选功能会用到云端模型（连拍里两张实在分不出高下时让模型看一眼），
**默认关闭**。就算打开，发出去的也只是：

- 最长边 512 像素的小图（实测 33–35KB）
- 元数据全部剥掉（0 个 EXIF 字段、没有 GPS）
- 不发文件名、不发路径、不发拍摄时间

## 怎么判断一个选片程序好不好

如果你打算自己做类似的东西，这一节值得看 —— 我们在这上面栽过七次。

**最大的坑：指标涨了，但交出去的名单没变好。**

我们有六次遇到「两个指标单独都有效，融合之后指标更好看，但实际挑出来的
照片反而更差」。所以现在的规矩是：**只认最终名单命中了几张，不认中间指标。**

**第二个坑：不知道天花板在哪。**

我们一度给某个功能定了「准确率要到 90% 才算过关」。后来才测出来，
**照片主人自己重做同一道题，一致率只有 50%**。90% 这条线比人类上限还高
40 个点 —— 定了等于没定。

想深入了解怎么测：[测量方法](docs/MEASUREMENT.md)（也是给完全没接触过的人写的）

## 已知做不到的

写在这里而不是藏起来，因为你有权知道。

1. **风景照做不了。** 六个美学模型全部等于随机，二次验证过。
2. **混着人像和风景的文件夹会走错分支。** 程序按整个文件夹的人脸比例决定用哪套
   标准，而真实用户的文件夹就是混的。这是已知缺陷，还没修。
3. **只在一个人的照片上验证过。** 所有结论都建立在一位使用者的口味上。
4. **眼睛天生细长的人可能被误判。** 判断闭眼用的是固定阈值，理论上对不同眼型
   不公平。我们试过按人归一化，实测反而更差（因为它没法表达「这一组全都闭眼」）。
   正确的修法需要多人照片集才能验证 —— 目前**没有证据**，这是真实的公平性风险。
