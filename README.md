# PhotoFilterAgent

**旅行回来几百张照片，帮你挑出值得留的那几十张。**

照片不离开你的电脑，不联网，不花钱。

---

## 它能帮你到什么程度

先说清楚，免得你抱着错的期待往下看。

我们拿一批真实的旅行照片做过测试：**309 张人像**，照片的主人自己从里面
挑出了 **20 张最喜欢的**。然后让程序在不知道答案的情况下挑一遍：

| 让程序挑 | 撞上你心头好的 | 如果闭眼乱挑 |
| --- | --- | --- |
| 10 张 | 3 张 | 0.6 张 |
| **20 张** | **6 张** | 1.3 张 |
| 50 张 | 10 张 | 3.2 张 |

它比乱挑好四五倍，但**挑 20 张里也就 6 张是你真想要的**。

所以它干的事是：**把 309 张缩到 20 张，让你在这 20 张里挑。**
你少翻 289 张，最后拍板的还是你。

它不会替你决定。**如果你想要一个能直接发朋友圈的成品，这个工具不是。**

---

## 它是怎么想的：把一件事拆成三步

「帮我挑照片」听起来是一件事，其实是三件，而且**难度天差地别**。

### 第一步：扔掉明显不能要的

闭着眼的、糊掉的、低头看地的。

**这一步最简单，因为没有争议。** 一张照片眼睛闭没闭，你看是闭的，
我看也是闭的，十个人看都一样。

程序做的事：用你 Mac 自带的人脸识别，量一下眼睛睁开了多少，太小就扔掉。

**这里有个讲究：宁可少扔，不能错扔。**

```
少扔了（该删的没删）→ 你多翻几张，没什么损失
错扔了（好照片被删）→ 你永远看不到它了
```

两种错误的代价完全不一样，所以程序设得很保守。实测下来，
在照片主人标注过的那批里，**它扔掉的照片没有一张是主人想留的**。

### 第二步：连拍的六张，只留最好的一两张

你按了六下快门，其实只需要一张。

**这一步中等难度。** 这六张几乎一模一样 —— 光线一样、构图一样、
清晰度一样，差别只在表情和眼神。差别少，反而好比较：
你问十个人「这六张哪张最好」，大部分人会指向同一两张。

程序做的事：先把长得几乎一样的照片认成一组，然后组内两两比较，
胜者留下继续应战，最后留下的那张当代表。

**为什么是两两比较，不是各自打分？** 因为「给一张照片打 7 分」这件事
非常不可靠 —— 同一张照片让同一个模型打两次，分数能差出一大截。
但「这两张哪张更好」就稳得多。**有参照物的判断，比凭空打分可靠。**

### 第三步：从剩下的里面选出最值得留的

**这一步最难，而且难在性质上，不是难在技术上。**

前两步问的是「**这张照片**好不好」—— 有客观答案。
第三步问的是「**你**想留哪张」—— 答案在你脑子里，照片本身没有这个信息。

同一批照片，你和你朋友挑出来的会是两批不同的照片，谁也没错。

程序能做的有限，目前最管用的一招是**保证时间上的覆盖**：

我们发现，人自己挑照片时是「这段行程的每一段都挑几张」；
而程序不管的话，会**把最好的那一段整段端走** —— 20 张里 14 张来自同一个
十几分钟的片段，剩下大半天的照片一张没有。

所以程序会把照片按拍摄时间切成十段，每段最多挑几张。
这一条改动，是所有改动里效果最明显的。

---

## 一句话总结这三步

```
第一步  谁看都一样的事      → 程序做得好
第二步  大部分人会同意的事   → 程序做个八九不离十
第三步  十个人十个答案的事   → 程序只能帮你缩小范围
```

**越往后越主观，程序能帮的忙就越少。** 这不是技术没做到位，
是问题本身的性质。

## 怎么用

### 你需要有

- 一台 Mac（要用到苹果自带的人脸识别）
- Python 3.9 或更新
- 一个装着照片的文件夹

### 装

```bash
cd ranker
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

第一次会自动下载几个模型（大约 3.6GB），之后就不用了。

### 跑

```bash
python -m photofilter_rank.cli pick ~/Desktop/我的照片 --target 20
```

`--target 20` 就是「帮我留 20 张」。

程序会打印一份名单。**它不会动你的原图** —— 不移动、不删除、不改名、
不覆盖。想把选中的复制出来，要你再单独给一条命令。

第一次跑 300 来张照片大约 5 分钟（要建缓存）。
同一批照片再跑只要 1.6 秒。

### 想先小规模试试

```bash
python -m photofilter_rank.cli scan ~/Desktop/我的照片
```

`scan` 只数一下有多少张、多少张有人脸，几秒钟就出结果。

## 你的照片会去哪里

**哪里都不去。**

所有的分析、打分、比较都在你自己的电脑上完成。不需要注册，
不需要 API Key，不需要联网（除了第一次下载模型）。

有一个**默认关闭**的可选功能，会在「连拍里两张实在分不出高下」时
让云端模型看一眼。就算你打开它，发出去的也只是：

- 最长边 512 像素的小图（一张 30 多 KB）
- 拍摄时间、地点、相机型号等信息全部剥掉
- 不发文件名，不发文件路径

原图永远只读，不会离开你的硬盘。

## 它做不到的

写在这里而不是藏起来，因为你有权提前知道。

**1. 风景照做不了。**
我们单独测了 161 张风景照，六个业界通用的美学评分模型，
结果全都和抛硬币一样。这不是没调好，是这条路走不通。
如果你的照片主要是风景，这个工具帮不上忙。

**2. 人像和风景混在一起的文件夹会出问题。**
程序会看整个文件夹里有多少张有人脸，据此决定用哪套标准。
如果你的文件夹是混的（大部分人都是），它可能整批用错标准。
这是已知缺陷，还没修。

**3. 只在一个人的照片上验证过。**
上面所有数字都来自一位使用者、一批照片。换个人、换批照片，
表现可能不一样。

**4. 眼睛天生细长的人，可能被误判成闭眼。**
程序用的是固定标准，理论上对不同眼型不公平。我们试过按每个人自己的
基准来判断，但没有足够的数据验证。**目前没有证据证明它是公平的**，
这是个真实存在的问题。
